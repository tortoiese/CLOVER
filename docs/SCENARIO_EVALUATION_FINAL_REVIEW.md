# CLOVER 최종 평가 설계: 알고리즘·시나리오·결론

2026-11-13. 시나리오 v3 최종 문서 검수. **설계는 평가 목적에 맞다. 실제 지도·작업 trace·부하 보정이 끝난 실행 입력은 아직 아니다.** 새62조건을 실행하거나 우수 알고리즘을 확정한 문서가 아니다.

목적은 같은 공장·같은 수요에서 **계획의 이득이 계산 비용보다 커지는 조건**을 찾고, 환경별로 사용할 정책과 추천을 보류할 범위를 정하는 것이다. 물리적 자원 증설 효과와 알고리즘 변경 효과를 구분한다. 자세한 제원 후보는 [시나리오 설계](SCENARIO_DESIGN_v3.md), 전체 요구와 후속 작업은 [PRD](PRD_ALGORITHM_EXPERIMENTS_v2.md)에 있다.

## 1. 어떤 알고리즘을 비교하는가

| 정책 | 쉬운 의미 | 평가 범위·질문 |
|---|---|---|
| baseline | 작업은 들어온 순서, 로봇은 돌아가며 배정 | 12가족 전체의 단순 정책 대조군 |
| optimized | 거리·배터리·대기·납기를 보고 빠르게 선택 | 12가족 전체의 실용 기준. 가중치 고정 |
| rh_milp_grid | 가까운 미래의 배정·이동·충전·자원 사용을 함께 계획 | 12가족 전체. 휴리스틱보다 운영 성과가 좋아지는가 |
| rh_cpsat_linear | MILP와 같은 격자 계획 문제를 CP-SAT으로 풂 | 12가족 전체. 같은 문제 표현에서 backend 선택이 어떤 영향을 주는가 |
| rh_cpsat_native | 시간 구간 중심의 별도 CP-SAT 계획 모델 | 우선 S01/S04/S08/S11. 품질·계산량의 실용 균형은 어떠한가 |
| assignment_milp_legacy | 기존 배정 MILP 정책 | 배정 정책과 RH 정책 패키지의 기전 대조. RH의 한 기능만의 효과를 분리한 실험은 아님 |
| rh_cpsat_interval | 공통 격자 계획의 interval 표현 | 같은 문제의 표현 차이를 보는 보조 대조 |

기능·물리 계약 검사는 7종 모두 한다. 본문에서 **핵심4종**은 baseline/optimized/rh_milp_grid/rh_cpsat_linear를 뜻한다. 마지막 두 보조 정책의 대규모 실행량은 아직 확정하지 않았으므로 62조건 전부의 최종 후보라고 표시하지 않는다. native가 시험되지 않은 가족에서 native를 추천하려면 E2 공개 전에 해당 평가 범위를 추가·고정해야 한다.

두 비교를 나눈다.

1. **운영 정책 비교:** 같은 초기 상태·작업·교란을 입력하고 공장을 끝까지 실행한다. 이후 상태가 정책별로 달라지는 것은 결과다. 주요 근거는 공통 D1이며 준비·판단·fallback 비용을 포함한다.
2. **동일 문제의 backend 비교:** 같은 snapshot·후보·격자·목적·hint·예산을 MILP/linear CP-SAT/격자 interval에 준다. closed-loop의 서로 다른 상태를 solver 자체 비교라고 부르지 않는다. 작은 의미·최적값 검증은 구현돼 있지만 실험용 snapshot 묶음·집계는 추가 준비 대상이다.

native의 해상도·방문 수·후보 범위가 다르면 별도 운영 설정으로 표시한다. 모델을 더 크게 보았기 때문에 좋은 결과와 solver 자체의 이점을 혼동하지 않는다.

## 2. 어떤 시나리오로 무엇을 알아내는가

모든 행에서 핵심4종을 비교한다. “주 비교값”과 함께 완료·미완료·취소·에너지·판단 지연·fallback·실패를 공통 기록한다. 아래 결론은 **실험이 답해야 할 질문**이다.

| 시나리오 | 주로 바꾸는 조건 | 주 비교값 | 도출하려는 결론 |
|---|---|---|---|
| S00 여유·대조 | 무수요/저부하, 입장 대수가 같은 폭1.3/1.8m | 서비스 성과와 계산 비용 | 단순 정책으로도 충분한 범위와 불필요한 계산 비용이 있는가 |
| S01 공동배차 | 작업별 적합 설비1/2/4개 | 전체 완료시간·총 이동, 미완료 | 배정 선택지가 많을 때 공동 계획의 이득이 생기는가 |
| S02 좁은 통로 | 폭1.3/2.2/3.1m, 동일 반대편 작업 배치 | 배치 완료시간·통로 대기·미완료 | 정책의 순서 조정 효과와 통로 용량 증가 효과를 구분할 수 있는가 |
| S03 교차로 | 같은 노드의 intersection/waypoint | 실제 교차로 점유·대기·완료 | 공유 교차로 제약이 병목에 미치는 영향과 정책별 대응은 어떠한가 |
| S04 충전 | 슬롯·슬롯당 충전율·초기 SOC 분포 | 완료·충전 대기·에너지 수지·로봇별 충전 반복 | 충전 계획의 이득이 언제 생기며 초기 배터리 효과가 사라져도 유지되는가 |
| S05 설비 집중 | 단일 설비 수요25/70/90%, 적합 설비는 고정 | 설비 대기·backlog·완료 | 배정 정책으로 해결할 수 없는 설비 용량 한계는 어디인가 |
| S06 긴급·몰림 | 긴급0/5/20%, 총 작업 수가 같은 burst×2/×4 | 긴급 응답·납기, 일반 작업 나이·미완료 | 몰림에 대응하면서 일반 작업을 계속 미루지 않는가 |
| S07 이종 로봇 | 속도 혼합 또는 폭 혼합 | 완료·이동·로봇별 대기/담당량·도달성 | 서로 다른 물리 특성에 맞게 일을 나누는가 |
| S08 다층 | 캐빈1/2개 또는 초기 캐빈 층 | 배치 완료시간·캐빈 대기·공차 이동 | 캐빈 경쟁에 계획이 도움이 되는가, 캐빈 증설 효과는 얼마인가 |
| S09 교란 | 설비/충전 정지·복구, 퇴역·취소·폭 변화 | 무교란 대비 서비스 손실·미완료·stale/fallback | 환경이 바뀐 뒤 안전하게 새 상태에 적응하는가 |
| S10 지속 과부하 | 명시한 용량 상한 초과 도착률 | backlog 증가·최고령 작업·납기 위반 | 감당할 수 없는 수요에서 어느 정책이 서비스 손실을 줄이며 어디서 자원 증설이 필요한가 |
| S11 규모·계산 예산 | 예산0.5/2/10s, 로봇4/8대, 별도64/256노드 지도 | D1 성과·시간 초과·fallback·메모리 | 좋은 계획을 제한 시간 안에 만들 수 있는 범위는 어디인가 |

깊게 보는 핵심8가족은 S00/S01/S02/S04/S06/S08/S10/S11이다. S03/S05/S07/S09는 보조4가족이지만 기능·기전 검증을 생략하지 않는다. native의 추가 비교는 S01/S04/S08/S11이다.

S01/S02/S03/S08의 유한 배치는 전체 작업을 끝낸 경우 완료시간을 비교한다. 일부만 끝났다면 미완료와 현재 나이를 함께 보고, 완료시간을 임의로 채우지 않는다. S05의 고정 설비 작업을 다른 설비로 옮길 수 있다고 해석하지 않는다. 그 선택의 효과는 S01에서 본다. S09는 복수 적합 설비를 사전 고정하며, 퇴역·취소에는 원상복구 시간을 정의하지 않는다.

S11은 노드 수뿐 아니라 대기 작업 수·후보 포함/제외·실제 모델 크기를 기록한다. 256노드 지도는 별도 환경이며, 노드 수만으로 solver 복잡도나 정책 차이를 설명하지 않는다.

## 3. 단일 병목 외에 확인할 복합 상황

| 2×2 블록 | 질문 |
|---|---|
| X01 통로 폭×초기 SOC | 에너지가 부족한 시작 상태에서 통로 압박의 정책 차이가 커지는가 |
| X02 충전 슬롯×긴급 비중 | 충전 경쟁 중 긴급 대응과 일반 작업 보호가 양립하는가 |
| X03 캐빈 수×위층 목적지 비중 | 위층 수요가 달라질 때 캐빈 증설과 계획의 효과가 달라지는가 |
| X04 처리시간 변동×부하 | 실제 작업시간의 불확실성과 혼잡이 겹쳐도 계획이 유효한가 |

기본46조건+복합16조건=62개 설계 조건이다. 복합 블록은 우선 핵심4종으로 평가한다. 같은 알고리즘에서 시설 조건을 바꾼 효과와, 같은 시설 조건에서 알고리즘을 바꾼 효과를 각각 계산한다. 예를 들어 모든 정책이 캐빈2개에서 빨라졌다는 사실만으로 CP-SAT의 우수성을 주장하지 않는다.

## 4. 최종적으로 만들 결과

다음은 사전 가설이며 결과가 아니다.

- 저부하나 짧은 예산에서는 휴리스틱의 빠른 판단이 유리할 수 있다.
- 배정 선택과 충전·공유 자원 사용이 결합되면 RH가 유리할 수 있다.
- CP-SAT native의 표현이 이득을 줄 수 있지만 큰 모델의 build/solve 비용으로 손해가 날 수도 있다.
- 물리 용량이 모자라면 정책을 바꾸어도 수요 전체를 처리할 수 없다. 병목 자원 증설과 서비스 우선순위의 문제가 남는다.

최종 산출물은 “MILP가 최고”라는 문장이 아니라 아래의 **검증된 적용 조건표**다.

| 결과 항목 | 채워야 할 내용 |
|---|---|
| 환경 | 부하·자원 압박·로봇/지도·목적지/적합 설비·교란·계산 예산의 검증 범위 |
| 권장 정책 | 실제 비교한 정책 ID와 정확한 설정/버전 |
| 근거 | 휴리스틱 대비 주 지표 차이·불확실성·지도/paired 표본 수 |
| 비용·제한 | 판단 지연·메모리·fallback·실패·납기·일반 작업 기아 |
| 판정 | 권장 / 사전 기준 내 동등 / 불확실 / 예산·지원 범위 밖 |

납기·미완료·실패 한도를 지키면서 사전 정의한 실용 개선을 보이는 정책을 후보로 삼는다. 동등성은 따로 정한 허용 차이와 분석으로 판단한다. 단순히 통계적으로 유의하지 않다는 이유로 동등이라고 하지 않는다. 효과가 불확실하면 휴리스틱을 유지하거나 추천을 보류한다. 선택 규칙을 학습한다면 실제 배포 때 관찰 가능한 특징만 사용하고 새 지도/seed에서 검증한다. 자동 선택기는 후속 구현 대상이다.

## 5. 실행 전 최종 검수 사항

1. 실제 좌표·로봇·설비·충전·캐빈·초기 상태와 실행용 Scenario JSON을 작성한다. 원문이 언급한 상세MD2개/계산기 실제 파일은 아직 검수 대상에 들어오지 않았다.
2. 지도 기준 λ를 보정하되 비교 블록의 절대 수요는 고정한다. 미래 작업·처리 noise는 정책에 보여주지 않는다.
3. 같은 입력을 쓰는지 확인하고 자원 존재·경로·사용 가능성을 검사한다. 모든 정책에 양수 대기나 동일 캐빈 사용을 요구해 결과를 골라내지 않는다.
4. E0 기능·기전 → E1 training/validation 및 설정 동결 → E2 새 환경 held-out → E3 새 stress → P6/R7 결론 순서로 진행한다. 기본 휴리스틱 가중치는 고정한다.
5. D0와 D1을 구분한다. 운영 추천은 계산·controller 비용까지 포함한 공통 D1을 중심으로 하고, D0로 계획 선택의 효과를 해석한다.
6. 진행 중 대기 나이를 완료 대기 P95에 섞지 않는다. 실패·미완료·취소와 초기/최종 SOC도 모두 남긴다.
7. 3seed는 파일럿이다. 완전 결정적 배치는 지도·초기 배치·작업 순서 변형으로 반복하고, 설정·실용 기준·표본 배분은 본 실험 전에 정한다.

최종 문서 검수는 설계 정합성에 대한 것이다. 실제62조건의 입력 검증·자원 노출·부하 검증·본 실험·suite 통계는 남아 있다. 기존452개 CI 통과는 코드 회귀 근거이며 이62조건의 성능·알고리즘 우열을 증명한 것은 아니다.
