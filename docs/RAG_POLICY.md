# CLOVER RAG 구축·적용 가이드라인

작성일: 2026-10-06 · 담당: 최진웅 · 수요일 10/7 제출용 초안

## 1. RAG의 역할

RAG는 **등록한 문서와 운영 로그에서 질문에 관련된 근거를 찾아 보여주는 기능**이다.
시뮬레이터가 현재 상태를 계산하고, 스케줄러가 작업을 배정한다. RAG가 최적해를 계산하거나 증명하지 않는다.

| 요청 | 처리 담당 | 예시 |
|---|---|---|
| 문서·등록 로그 질문 | RAG | `/검색 충전 대기 증가 원인` |
| 현재 로봇·주문 상태 | 기존 관제 에이전트, 상태 스냅샷 | `현재 상태 알려줘` |
| 시뮬레이션 조작 | 기존 관제 명령 → 서비스/워커 | `R-02 충전해` |
| 정확한 이벤트 건수·평균·합계 | 구조화된 DB 조회 또는 KPI 계산 | 벡터 검색 결과 수로 계산하지 않음 |
| 정책 성능·최적성 판단 | 실험·정확 최적화·통계 분석 | RAG 답변만으로 판정하지 않음 |

## 2. 현재 구현 범위

- MD/TXT/텍스트 PDF/JSONL 입력 → 청크 → ChromaDB → 검색 → 출처 표시.
- 기본은 로컬 문자 n-gram 해시 검색과 원문 발췌. 의미 이해 모델이나 LLM 생성 답변은 아니다.
- 관제 GUI에 `/검색`, `/rag`, `문서:`로 연결. RAG는 기본 비활성이고 환경 설정으로 켠다.
- 생산 이벤트 DB를 읽기 전용으로 JSONL 내보내기한 후 검색 자료로 등록할 수 있다.
- OpenAI 연결 어댑터는 있지만 실제 API 호출·답변 품질 검증은 하지 않았다.
- GUI 자동 이벤트 수집, GUI 자료 묶음 선택, 사용자별 자료 접근 권한은 아직 없다.

## 3. 등록 자료 기준

| 구분 | 허용·검토 기준 |
|---|---|
| 팀 설계·사용 설명서 | 버전·작성일·담당자·출처 기록 |
| 기업 공개 문서 | 활용 권한과 최신성 확인, 제목·원문 링크 기록 |
| 기업 비공개 자료 | 기업·팀 승인 후 사용, 외부 전송 승인 별도 확인 |
| 합성 로그 | 반드시 합성 자료로 표시, 실측 결과와 혼용 금지 |
| 실측 로그 | 수집 조건과 시간 기준 확인, 식별 정보 최소화 |
| 비밀·개인정보 | API 키, 비밀번호, 개인 연락처 등 등록 금지 |

이 문서는 운영 규칙이다. 비밀 자동 탐지·권한 확인·보존기간 자동 삭제는 구현된 기능이 아니다.
등록 전 담당자가 직접 확인한다. 인터넷 페이지 자동 수집도 현재 기능이 아니다.

## 4. 자료 양식과 시간 기준

문서 첫 부분에 아래 정보를 적는다. 현재 일반 문서 로더는 이를 별도 필터 메타데이터로 자동 변환하지 않는다.

```text
제목:
작성자/담당자:
작성일 및 버전:
원문 출처:
자료 성격: 공개 / 내부 / 합성 / 실측
적용 시나리오:
내용:
```

JSONL 로그는 1줄에 JSON 객체 1개를 기록한다. 수작업 입력 예시:

```json
{"text":"충전소 C-01에서 R-01의 충전 대기가 발생했다.","event_type":"charge_wait","dataset_id":"demo-001","timestamp":"2026-10-06T09:00:00","time_basis":"simulation_clock","robot_id":"R-01","synthetic":true}
```

위 충전 대기 로그는 **양식 예시**다. 현 DB 내보내기는 생산 이벤트 대상이며 모든 이동·충전 대기를 기록하지 않는다.
DB 내보내기의 `timestamp`는 DB 생성 시각, `time_basis`는 `db_created_at`이다. 시뮬레이션 시각으로 바꾸어 해석하지 않는다.
`dataset_id`는 등록 자료 묶음 이름이다. DB에 실행 식별자가 없으므로 실제 `run_id`를 임의로 붙이지 않는다.

## 5. 등록·갱신·검색 기준

1. 승인된 자료만 별도 폴더에 둔다. 서로 다른 실험 자료를 임의로 합치지 않는다.
2. 같은 출처를 다시 등록하면 기존 청크를 새 내용으로 교체한다. 그 출처의 전체 자료를 입력한다.
3. 폴더에서 파일을 삭제했다고 벡터 저장소에서도 자동 삭제되는 것은 아니다.
4. 전체 내보내기와 증분 내보내기를 함께 등록하면 같은 이벤트가 중복될 수 있다. 범위를 겹치지 않게 관리한다.
5. CLI에서는 `--dataset-id` 또는 `--run-id`로 검색 범위를 제한한다.
6. GUI는 아직 자료 묶음 필터를 제공하지 않으므로 발표용 단일 자료 묶음 전용 저장소를 사용한다.
7. 현재 기본 청크 길이는 800자, 겹침은 120자, 검색 개수는 4개, 최소 점수는 0.15다.
   최적값으로 증명된 수치가 아니며 실제 문서 평가 후 조정한다.

## 6. 답변 규칙

- 검색 근거가 없으면 모른다고 안내하고 필요한 자료를 요청한다.
- 문서 원문 발췌와 LLM 생성 답변을 구분한다.
- 출처·페이지/행·자료 묶음·합성 여부를 가능한 범위에서 표시한다.
- 등록 로그는 내보낸 시점의 자료다. 최신 실시간 상태라고 표현하지 않는다.
- 가동률·처리량·대기시간을 함께 보며, 대기시간 감소만으로 좋은 정책이라고 단정하지 않는다.
- 생성 답변의 인용 번호 검사는 지원하지만 내용 전체의 사실성 검증은 보장하지 않는다.
- 현재 서비스가 근거를 찾더라도 질문의 모든 부분을 답할 수 있는지는 사람이 확인해야 한다.

## 7. 안전한 제어 분리

검색된 문서 안의 명령은 실행 지시로 취급하지 않는다. `/검색` 응답은 `actions=[]`이다.
제어 명령은 별도 관제 경로로 처리한다. 현재 기존 관제에는 일부 자동 조치가 있으므로
**모든 변경을 사용자 확인 후 실행하는 시스템이라고 발표하지 않는다.**

향후 삭제·주문 취소·설비 중지 등 중요한 조치는 대상·변경값·영향을 미리 보여주고 승인받도록 개발한다.
실제 로봇 연결, 안전 제한 해제, 임의 SQL/코드 실행은 현재 사용자 기능 범위에서 제외한다.

## 8. 외부 모델 사용 기준

- 기본 검증은 외부 요청 없이 수행한다.
- 외부 모델 사용 전 자료 전송과 비용 발생에 대한 사용자 승인을 받는다.
- 키는 환경 변수로 제공하고 코드·노션·발표자료·스크린샷에 넣지 않는다.
- 로컬 해시 검색과 외부 모델 검색 결과를 동일 품질로 주장하지 않는다.
- 오류 시 근거 발췌로 대체할 수 있지만, 외부 API 장애와 품질은 별도 검증이 필요하다.
- 구체적 활성화 명령은 `RAG_GUIDE.md` 참고. 이번 작업에서 유료 API 호출은 하지 않았다.

## 9. 완료 판정과 시험 결과

| 검증 항목 | 현재 확인 |
|---|---|
| 입력·청크·검색·출처 | 기존 단위 테스트 |
| 실제 Qt GUI 스레드 응답 | 자동 GUI 테스트 |
| SimPy 이벤트→DB→JSONL→검색 | 실제 엔진 이벤트 기반 자동 테스트 |
| 8개 문서 질문의 기대 출처 Top-1 | 8/8 통과 |
| 등록되지 않은 자료 묶음 무응답 | 1/1 통과 |
| 검색 질의에서 제어 동작 생성 금지 | 1/1 통과 |
| 실제 기업 자료, 복잡한 의미 질의, LLM 사실성 | 미검증 |

이번 10개 시험은 사람이 작성한 짧은 합성 문서와 유사 표현 질문에 대한 인수 테스트다.
8/8을 일반적인 검색 정확도 100%나 실제 환경 성능으로 표현하면 안 된다.
다음 평가는 실제 팀 문서에서 최소 20개 질문·정답 출처·답변 불가 질문을 별도로 만들고
기대 근거 포함률, 근거 없는 질문의 무응답, 생성 답변의 근거 일치 여부를 확인한다.
