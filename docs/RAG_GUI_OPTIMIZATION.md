# RAG GUI 운영안 비교 사용 가이드

## 구현 범위

기존 문서 검색과 관제 채팅에 조건 설정 → 독립 비교 실험 → 결과 조회 → 출처 설명을 연결한다.
기본은 로컬 검색이며 OpenAI API 호출 없이 사용한다. 자연어 전체를 해석하는 LLM 에이전트는 아니다.
최적화 의도가 섞인 지원하지 않는 명령은 안내하고 기존 즉시 제어 명령으로 전달하지 않는다.
기존 관제의 명시적인 로봇 추가·정책 표시 전환 기능은 유지한다.

이 변경은 기존 RAG PR #1의 `Feat/RAG`를 기반으로 하는 후속 변경이다.
기존 작업 폴더의 미커밋 관측 로그 기능은 이 브랜치로 복사하지 않았다. 별도 검토·통합 대상이다.

## 실행

Python 3.11+ 가상환경에서:

```bash
cd robot_factory_sim
python -m pip install -r requirements.txt
CLOVER_RAG_ENABLED=1 CLOVER_RAG_PROVIDER=local python main.py
```

현재 로컬 작업 폴더에서 기존 가상환경을 사용하는 경우:

```bash
cd "/Users/jiyun/Documents/ChatGPT/캡스토디자인(IC-PBL)/CLOVER-RAG-orchestration/robot_factory_sim"
CLOVER_RAG_ENABLED=1 CLOVER_RAG_PROVIDER=local ../../.venv/bin/python main.py
```

GUI 실행은 기본 공장 DB와 RAG 저장소를 초기화할 수 있다. 비교 실험은 DB·실행 중 공장을 변경하지 않는다.
새로운 `operating_policy.md`는 기존 검색 저장소에도 자동 등록한다. 기존 사용자 문서는 유지한다.
채은의 산식 문서를 추천 설명 근거로 등록하려면:

```bash
python -m agent.rag.cli ingest /path/to/roi-policy.md --policy
```

`CLOVER_RAG_DATA_PATH` 또는 CLI `--store`로 GUI와 동일한 저장소를 지정한다.
`--policy`는 문서를 추천 근거로 검색하는 메타데이터다. 문서의 지시가 실행 코드나 산식을 변경하지 않는다.

## 발표 시나리오

1. 공장 설정에서 로봇·충전소 대수와 설비 위치를 설정한다.
2. [운영안 비교] → [비교 조건]에서 실측 또는 합의한 비용 값을 입력한다.
3. 발표에서만 [발표용 예시 단가 입력]을 사용한다. 결과에 **예시값 · 가상 비용 모델**이 표시된다.
4. [현재 GUI 구성으로 비교 실행] 또는 채팅 `/최적화`를 입력한다.
5. [결과·검증 범위]에서 베이스라인과 MILP 배정안을 비교한다.
6. `/추천`, `/ROI`, `/근거`로 계산 결과와 운영 문서의 출처를 설명한다.
7. 설정을 바꾸고 재실행한다. 이전 결과와 실험 ID를 혼동하지 않는다.
8. [실험 결과 JSON 저장]으로 설정·주문·평가 시각·시드·원시 반복 결과를 저장한다.

## 채팅 명령

| 입력 | 기능 |
|---|---|
| `/최적화 도움말` | 지원 조건, 단위, 제한 안내 |
| `/조건 기간=120 반복=3` | 비교 조건 설정, GUI 양식과 동기화 |
| `/조건 건당매출=1000 전력단가=150 배터리Wh=1 이동단가=1 고정비=100 AI비=0` | 사용자 비용 가정 입력 |
| `/최적화` 또는 `비용 줄여줘` | 현재 GUI 구성으로 새 비교 실험 |
| `충전기 2대 유지하고 비용 줄여줘` | 활성 충전소가 2개인지 확인한 뒤 고정 구성 비교 |
| `/비교` 또는 `베이스라인 비교해줘` | 마지막 저장된 결과 표시, 재계산 없음 |
| `/추천` 또는 `왜 추천했어?` | 마지막 결과와 RAG 운영 근거 |
| `/ROI` 또는 `ROI 설명해줘` | 마지막 수익 지표와 산식 근거 |
| `/근거` | 등록된 운영 기준 문서 검색 |
| `/검색 ROI 산식` | 기존 일반 RAG 검색 |

채팅 조건에는 `계획구간`, `재계획`, `시드`, `충전효율`도 사용한다.
로봇·충전소 대수와 위치는 GUI 공장 설정에서 변경한다. 자연어 임의 위치 변경을 추측하지 않는다.
전력 단가는 원/kWh, 배터리Wh는 상대 배터리 1단위당 Wh, 이동단가는 전력 제외 원/m이다.
매출 또는 Wh 환산값이 미설정이면 ROI·비용 추천을 보류한다. 분모 0은 `미산정`으로 표시한다.

## MILP 모델과 비교 실험

- SciPy/HiGHS `milp`로 **현재 유휴 로봇의 단일 작업 배정**을 계산한다.
- 이진 변수: 로봇–작업–설비 후보의 선택 여부.
- 제약: 로봇/작업/설비당 신규 배정 1개, 사용 중·이동 예약 설비 제외, 경로 도달 가능,
  작업 및 충전소 복귀 예상 에너지 이후 배터리 여유, 계획 구간 내 예상 이동·작업 시간.
- 목적: 배정 수 우선 최대화 후 우선순위·이동·예상 에너지 점수 최소화. 전체 ROI의 직접 최적화가 아니다.
- 재계획 주기마다 배정을 갱신하고 진행 중 작업은 유지한다.
- 충전 시점·충전소 선택은 기존 규칙이며 슬롯은 SimPy 자원으로 제한한다.
- 전체 공정 순서, 다단계 작업 일정, 시간대별 전력 요금, 위치·대수 탐색은 모델에 포함하지 않는다.
- 각 solve의 시간 제한은 0.25초, 상대 격차 허용값은 0.1%다. 유효한 정수 해가 없으면 배정하지 않는다.
- 전체 비교의 계산 시간 제한은 약 30초이며 창 종료 시 취소를 요청한다.

동일한 공장 구성·초기 만충전·기본 배치에서 베이스라인과 MILP 배정안을 반복 실행한다.
진행 중 공장의 위치·잔량·작업을 이어받는 실시간 예측은 아니다.
진행 중 주문이 있으면 동일한 남은 주문만 평가하고, 없으면 동일한 합성 포아송 수요를 주입한다.
주문/작업 순번 기반 공통 처리시간 난수를 고정해 배정 순서에 따른 난수 뒤바뀜을 줄인다.
처리량과 대기시간은 기존 KPI 정의를 사용한다. 대기시간은 관측된 표본의 평균이며 미처리 작업을 제외할 수 있다.

## 수익과 오차 해석

산식은 `utils/comparison_models.py`에 구현되어 있으며 문서를 검색해 동적으로 실행하지 않는다.
매출은 완료 **공정 작업** 기준이다. 완제품 기준 모델이 필요하면 별도 계측해야 한다.
이동·작업 배터리 소모를 사용자가 입력한 Wh 환산값 및 충전효율로 보충 전력으로 추정한다.
실제 콘센트 사용량이나 설비·유휴 전력을 측정한 값이 아니다.
고정비는 평가 기간 전체 비용이다. 자본 투자·감가상각 등을 포함할지 팀이 비용 모델에서 합의해야 한다.
AI비는 추천안의 평가 기간 추가 비용으로 입력하며 실제 API 비용 자동 집계는 아직 없다.
표의 ROI는 반복별 운영비 기준 ROI의 평균이다. 합산 매출/비용으로 계산한 ROI와 다를 수 있다.

다음 세 가지를 혼동하지 않는다:

1. **MILP 격차:** 개별 유휴 배정 모델의 목적함수 경계와 해의 차이. 전체 기간 최적성 증명이 아니다.
2. **평균 차이의 95% t 신뢰구간:** 독립 시드의 쌍대 정책 차이로 계산. 실제 공장 예측 오차가 아니다.
3. **실측 대비 오차:** 실제 공장 데이터로 모델을 검증해야 산출할 수 있으며 현재 구현 범위 밖이다.

순이익 차이 신뢰구간의 하한이 양수이고 평균 처리량이 감소하지 않을 때만 추천한다.
순이익 감소가 명확하면 베이스라인을 추천하며, 불확실하거나 비용 모델이 없으면 추천을 보류한다.
추천은 평가한 조건에서의 비교 의견이며 생산 목표·모든 납기 달성이나 실제 기업 수익을 보장하지 않는다.

## 검증 및 후속 작업

```bash
QT_QPA_PLATFORM=offscreen CLOVER_RAG_PROVIDER=local PYTHONDONTWRITEBYTECODE=1 \
  python -m pytest -q -p no:cacheprovider
```

실제 solver 실행, 재현성, 주문 반영, 부분 이동 에너지, Wh/kWh 및 ROI 산식,
잘못된 조건·혼합 제어 요청 거부, GUI 작업 스레드 비교·후속 출처 응답을 검사한다.

후속 작업: 팀의 완전한 Rolling Horizon MILP 일정 모델 연결, 실측 전력 보정,
완제품·설비 투자 ROI 비용 정의, 자유로운 자연어 해석, 저장 결과의 자동 검색 등록,
미커밋 관측 기록 기능 통합, 실측 데이터 기반 모델 검증.
