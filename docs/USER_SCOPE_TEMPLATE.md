# 사용자 정의 범위·입력 양식

작성일: 2026-10-06 · 담당: 최진웅 · 수요일 10/7 제출용 초안

## 1. 한 줄 원칙

**사용자는 공장 환경·로봇·주문·실험 목적을 정의하고, 시스템은 그 조건 안에서 정책을 비교한다.**
조건이나 목표가 달라지면 좋은 정책도 달라진다. 제안 정책을 모든 상황의 절대 최적해로 부르지 않는다.

## 2. 변경 권한 범위

| 항목 | 이번 사용자 기능 | 현재 지원 경로 |
|---|---|---|
| 공장 크기·설비·충전소·벽·문·경로 | 설정 가능 | 공장 설정 GUI, DB 저장 후 반영 |
| 로봇 종류 표시·배터리·속도·소모율·임계값 | 설정 가능 | 로봇 설정 표 |
| 주문 제품·수량·우선순위·납기·사용 설비 | 설정 가능 | 주문 GUI·기존 관제 |
| 시작·정지·배속·최소충전 모드 | 기존 명령 범위 내 | GUI·관제·엔진 파라미터 |
| 문서·등록 로그 질문 | 설정 활성화 후 가능 | `/검색 질문` |
| RAG 자료 등록·저장소·검색 필터 | 개발자/자료 담당 설정 | 환경 변수와 CLI, 일반 GUI 양식 없음 |
| KPI 중요도·정책 가중치·실험 반복 수 | 연구 양식으로 기록 | 일부 코드/실험 스크립트 설정 필요, GUI 구현 아님 |
| 실제 로봇 제어·임의 코드/SQL 실행 | 제외 | 현재 허용 기능 아님 |
| 개인별 역할·접근 권한 enforcement | 향후 과제 | 현재 인증·권한 시스템 없음 |

사용자가 AGV/AMR 문자열을 바꿀 수 있어도 운동학·적재량·센서 차이가 모두 모델링된 것은 아니다.
현재 로봇 차이는 주로 속도·에너지 파라미터로 반영된다.

## 3. 단위부터 통일

| 항목 | 현재 단위 | 주의 |
|---|---|---|
| 공장·좌표·설비 크기 | px, 1px=0.1m | 800×600px는 80×60m |
| 이동 속도 | m/s | 좌표 단위와 다름 |
| 작업 시간·시뮬레이션 시간 | sim-sec | 실제 실행시간과 다름 |
| 배터리 용량·소모·충전 | 상대 에너지 단위 | 근거 없이 Wh·W로 표기하지 않음 |
| 배터리 충전 임계값 | % | 용량의 상대 비율 |
| 충전율 | 에너지 단위/sim-sec | 용량 100, 충전율 2이면 단순 모델에서 50초 만충전 |
| 주문 납기 | 시뮬레이션 시각 기준 | GUI 입력은 남은 시간(시간), 내부 계산은 초 |
| 작업 발생률 | tasks/sim-sec | 주문 작업과 배경 작업을 구분 |

현 모델은 선형 에너지 근사다. 실제 충전 곡선·적재량별 소비·물리 충돌 회피까지 검증된 모델이 아니다.

## 4. 파라미터 명세

아래 ‘제안 범위’는 데모·실험을 위한 팀 초안이며 회사 제원이 아니다.
GUI 상한은 처리 가능한 규모를 보장하는 성능시험 결과가 아니다.

| 항목 / 필드 | 현재 GUI 또는 기본값 | 제안 검증·실험 범위 |
|---|---|---|
| 공장 가로·세로 / floor_width,height | GUI 0~5000px, 기본 800×600 | 반드시 양수. 초기 실험 400~1200px |
| 격자 간격 / grid_cell_size | GUI 0~500px, 기본 50 | 반드시 양수. 초기 실험 25~100px |
| 위치 / x,y | GUI 좌표 입력 0~5000px | 실제 공장 경계 안. 이동 시작·설비 접근점이 연결되어야 함 |
| 설비 크기 / width,height | GUI 0~400px, 기본 80×60 | 반드시 양수. 경계·통로와 충돌 점검 |
| 처리 평균 / avg_process_time | GUI 0~600초, 기본 5 | 양수. 예시 실험 5·10·20초 |
| 처리 표준편차 / process_time_std | GUI 0~120초, 기본 1 | 0 이상. 0은 결정적 시간 실험 |
| 충전소 슬롯 / capacity | GUI 1~20, 기본 2 | 정수. 충전소 개수와 별도로 기록 |
| 충전율 / charge_rate | GUI 0~50, 기본 2 | 양수. 예시 1·2·4 상대 단위/초 |
| 로봇 수 | 표 행 수, 기본 5대 | 초기 실험 5·10·16대. 한계 규모 별도 검증 |
| 배터리 용량 / battery_capacity | 자유 숫자 입력, 기본 100 | 유한 양수. 제원 없으면 상대 단위 100 고정 |
| 속도 / move_speed | 자유 숫자 입력, 기본 2m/s | 유한 양수. 민감도 예시 0.5·1·2m/s |
| 이동 소모 / battery_drain_rate | 자유 숫자 입력, 기본 0.5단위/m | 유한 0 이상. 0은 이동 에너지 무시 실험 |
| 충전 임계값 / charge_threshold | 자유 숫자 입력, 기본 20% | 0~100%. 예시 20·30·40%, 극단값 회귀 시험 |
| 주문 수량 / quantity | GUI 1~100000개 | 양의 정수. 로봇 작업 1건과 생산량 매핑 가정 기록 |
| 우선순위 / priority | critical/high/normal/low | 네 값 중 선택 |
| 납기 | GUI 0~72시간, 0=없음 | sim 기준. 실제 달력 납기와 구분 |
| 배속 | GUI 1·2·5·10배 | 표시·실행 속도, 물리 이동 속도 변경 아님 |
| 배경 발생률 / task_rate | 기본 0.12, 런타임 0.01~2 | tasks/sim-sec. 고정 입력으로 정책 비교 |
| 최소충전 / min_charge_mode | 기본 꺼짐 | 켜짐/꺼짐. 충전 목표는 시작 임계값 이상 보장 |

중요: 위 양수·유한값·경계·중복 ID 규칙은 **이번에 정의한 입력 기준**이다.
현재 코드가 모든 진입 경로에서 이를 검증하는 것은 아니다. 특히 로봇 표는 숫자 변환만 확인하는 부분이 있다.
강제 검증기·사용자 친화적 오류 표시·관제 명령 검증 통일은 후속 구현 대상이다.
예시 범위는 제품 안전 허용값이나 실제 공장 권장 속도를 의미하지 않는다.

## 5. 노션에 복붙할 환경 정의 양식

```text
[환경 정의]
시나리오 ID / 이름:
작성자 / 날짜 / 버전:
목적: 정상 / 주문 피크 / 충전 병목 / 설비 장애 / 기타
자료 성격: 합성 / 실측 / 혼합 (각 항목 출처 별도)
공장 크기: 가로 __ px × 세로 __ px (= __ m × __ m)
격자 간격: __ px
작업 설비: ID, 종류, 위치, 크기, 평균 처리시간, 표준편차, 가동 여부
충전소: ID, 위치, 슬롯 수, 충전율, 가동 여부
로봇: ID, 종류, 상대 배터리 용량, 속도, 이동 소모, 충전 임계값, 가동 여부
벽/문/장애물: ID, 좌표, 통과 가능 여부
경로: 노드, 엣지, 단방향/양방향, 설비 접근 노드
미모델링 항목: 적재량 / 충돌 회피 / 통신 지연 / 충전 곡선 등
입력 검토 담당 / 검토 결과:
```

```text
[주문·상황 정의]
제품명:
수량:
우선순위:
투입 시각: sim __ 초
납기: sim __ 초 또는 없음
사용 설비:
배경 작업 발생률: __ tasks/sim-sec
장애 이벤트: sim __ 초, 대상 __, 복구 sim __ 초
```

```text
[정책 비교 정의]
비교 목적: 생산량 우선 / 납기 준수 우선 / 비용 최소 / 균형
기준 정책: 현재 Baseline (라운드로빈 + 반응형 충전)
비교 정책: 현재 Optimized (가중 점수 배정 + 상황별 충전)
주요 평가 지표:
보조 지표 및 허용 악화 범위:
실행 기간: __ sim-sec
시드 목록 / 반복 수:
동일 조건: 맵, 주문, 로봇, 충전소, 시드, 기간
판정 기준: 사전 정의한 지표 개선 + 보조 지표 악화 여부
한계: 최적성 증명 / 실측 타당성 검증 여부
결과 저장 위치 / 데이터 묶음 ID:
```

목표 중요도는 평가 양식이지 현재 GUI의 가중치 설정 기능이 아니다.
현재 Optimized를 MILP·강화학습 구현으로 표기하지 않는다.

## 6. RAG 질문·제어 명령 양식

```text
[문서·로그 질문]
/검색 충전 대기 증가 원인과 근거 알려줘
자료 묶음: __ (CLI 필터, GUI는 전용 저장소 사용)
자료 기준 시점:
원하는 정보: 원인 / 운영 가이드 / 기록 내용
기대 출처:
```

```text
[관제 명령]
명령 예: R-02 충전해 / 현재 주문 현황 보여줘
대상 ID:
변경 내용:
실험 조건 변경 여부:
예상 영향:
승인자/기록: __ (운영 양식이며 자동 승인 UI는 미구현)
```

검색 질문은 제어하지 않는다. `/검색 로봇을 삭제해`를 입력해도 검색 응답 경로에서 삭제 동작을 만들지 않는다.
관제는 현재 규칙 기반으로 지원하는 표현만 처리하며 어떤 자연어도 이해하는 시스템은 아니다.

## 7. 초기 제출용 예시

| 항목 | 예시 값 |
|---|---|
| 시나리오 | S-CHARGE-01, 충전 병목 비교 |
| 맵 | 800×600px, 격자 50px, 접근 경로 연결 점검 |
| 로봇 | 10대, 상대 용량 100, 속도 1m/s, 소모 0.5/m, 임계값 20% |
| 생산설비 | 5개, 평균 10초, 표준편차 1초 |
| 충전소 조건 A/B | 2곳×각 1슬롯 / 2곳×각 2슬롯 |
| 충전율 | 2단위/sim-sec |
| 평가 기간 | 1800 sim-sec |
| 반복 제안 | 시드 42~51, 각 정책 10회 |
| 주요 지표 | 완료 작업 수·납기 준수·충전 대기·설비 가동률 |

이 표는 **실험 설계 예시이며 이번에 실행한 결과가 아니다.**
충전 슬롯 추가가 대기시간을 줄여도 생산량 변화와 자원 비용까지 함께 평가한다.
