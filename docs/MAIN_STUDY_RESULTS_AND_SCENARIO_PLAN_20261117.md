### 실행 순서와 완료 기준

1. **시간 검증 먼저 보완**: 기존216실패는 유지한다. 개발용 새 입력에서 관측 생성·직렬화·build·solve·validate·commit·publication 비용과 fallback 원인을 분해한다. 정적 지도 재사용·중복 직렬화 감소 등 실제 비용을 줄인다. 예비시간을 조정하려면 개발 자료와 전체2초 예산 안의 배분 근거를 먼저 확정한다. 결과가 좋아질 때까지 현재 실패 seed를 반복하지 않는다.
2. **수학 해의 품질과 운영 성능을 분리**: 공통 snapshot/D0 비교에서는 같은 후보·단위·목적·시간 예산으로 해 품질/feasibility/후보 제외를 본다. D1에서는 계산 중 공장이 움직이는 비용·기한·fallback을 포함한다. D0의 이득을 D1 운영 이득이라고 부르지 않는다. 성능 개선이 주 solver인지 fallback인지 수용률/이유를 함께 검토한다.
3. **소규모 새 파일럿**: 우선 S10/S07/S02의 개선 기전, S06의 바닥 효과, S08의3층, S11의 계산 한계를 검사한다. 개발3지도×3seed는 설계 검사이며 유의성 근거가 아니다. 유리한 성능만을 기준으로 발표할 시나리오를 고르지 않고 성공/실패/차이 없는 조건을 함께 등록한다.
4. **새 확인 실험 등록**: 변경한 구현/프로토콜·모든 변수/가설·표본·실용 차이·통계·가드레일을 잠그고, 이번 결과를 보지 않은 새 지도/seed에서 확인한다. 표본 수는 필요한 구간 정밀도/검정력을 바탕으로 정하며6지도×10seed 같은 숫자가 유의성을 보장하지 않는다. 원래 지도 변형만 늘리기보다 교차/루프/분기/승강 위치 등 독립 지도 유형을 추가한다.
5. **최종 선택 규칙 검증**: 기한 내 실행 가능성·안전성 → 처리량/긴급 SLA의 실용 차이 → 에너지·대기·계산 비용 순으로 판정한다. 실패/검열/미완료를 분모에 남긴다. 지원하지 못한 조건은 추천 보류로 남긴다. 이번 연구의 기본 정책을 결과에 맞춰 조용히 바꾸지 않는다.

첫 확인 우선순위는 **시간 계약 복구 → S10 부하 곡선/S07 이종성 → S06 난도/S08 다층 → 규모·복합 병목**이다. 어려운 시나리오를 늘려서 RH가 이기게 만드는 것이 아니라, 차이의 원인과 지원 한계를 재현하는 설계다.
