# CLOVER 후속 시나리오 담당자 작업 안내

작성일: 2026-11-19 KST · 상태: 설계안 / 입력 생성·실행 전

목표는 **로봇이 얼마나 바쁘고 충전 경쟁이 얼마나 클 때 공동 계획이 도움이 되는지** 확인하는 것이다. 현재 좋은 결과와 이점이 작은 결과를 모두 남겨 알고리즘 선택 기준을 만든다.

전체 구현·실험 계획은 [시뮬레이터 고도화 계획서](../../PRD_SIMULATOR_SCENARIO_ADVANCEMENT_20261119.md), 수치/조건ID는 [설계 초안JSON](design_draft.json)에 있다. 이 JSON은 기존 실행기에 바로 넣는 파일이 아니다. 실제 실행 입력으로 변환·감사하는 작업은 알고리즘/실험 기반 담당이 맡는다.

## 1. 먼저 만들 시나리오

단층 개발지도에서 부하3수준×충전슬롯3수준×도착형태2수준=18조건을 준비한다.

| 변수 | 수준 | 이렇게 둔 이유 |
|---|---|---|
|부하|기준λ의0.6·1.0·1.3배|여유·기준·높은 작업량에서 정책 차이를 확인|
|충전슬롯|1·2·4개|충전 경쟁이 어느 수준부터 문제가 되는지 확인|
|도착형태|원래 도착 / 같은 주문 수의burst4|주문 총량과 급증 효과를 구분|

기준λ는0.08tasks/s, 즉 기대값으로 분당4.8건이다. 배수별로0.048/0.080/0.104tasks/s(분당2.88/4.80/6.24건)를 사용한다. 이 값은 연구용 기준이며 실제 공장의 처리용량이 아니다. 같은λ라도 seed별 실제 주문수는 다르므로 생성 후 실현 주문수를 기록한다.

공통으로 유지할 값:

- 1층60×40m, 로봇8대, 서비스설비6개, 속도1.05m/s, 폭0.6m·길이0.8m
- 배터리60unit, 초기SOC60~80%의 같은 로봇별 목록
- 충전소1곳, 슬롯당0.25unit/s. 슬롯1/2/4의 총 명목 충전능력은0.25/0.50/1.00unit/s
- 처리시간8초·편차0, 이동0.1unit/m·작업0.1unit/s, 기본 통로폭5.0m
- 긴급15%, 일반 납기여유120초·긴급45초, 목적지 분산
- 초기 후보 관측창35분·준비5분. 최종 창은 실행 전 공통 검수에서 확정

각 조건에서 새 수요seed5개를 만들고, 각 입력을4정책에 똑같이 제공한다. 따라서90입력·360정책실행이다. seed5개는 개발 비교용이며 통계적 충분성의 보장이 아니다.

## 2. 가장 중요한 공정 비교 규칙

| 바꾸는 것 | 그대로 둘 것 | 검사할 것 |
|---|---|---|
|충전슬롯|작업목록·도착시각·납기·목적지·SOC·충전속도/슬롯|trace hash와 초기상태 hash 동일|
|도착형태|같은실현작업수·UID·목적지·우선순위·처리잡음·상대납기|도착시각과 그에 맞춘 deadline만 변환|
|부하|지도·물리·납기여유·충전·정책설정|모든정책에 같은 절대도착률. 서로 다른부하의 작업집단은 다를 수 있음|
|정책|전체입력과결정시간예산|정책별입력을사후조정하지않음|

“분당6.24건”은 평균 도착률이며 매분 정확히 그 수가 들어온다는 뜻이 아니다. burst4도 전체 작업 수를4배로 늘리는 입력이 아니라 같은 주문을 특정 구간에 모으는 변환이다. 실제 급증구간과 경계의 유입 수를 생성 후 확인한다.

입력이 어려워졌다고 자동으로 병목 실험이 되는 것은 아니다. 충전 부족을 조사한다면 실제 소비·충전·슬롯 점유·대기가 발생해야 한다. 반대로 저부하에서 대기가0인 것은 정상 대조 결과다.

## 3. 지도는 두 번째 묶음으로 준비

개발지도와 구조가 다른3개를 준비한다. 단순한 지도명·seed·축척 변경은 새 독립지도가 아니다.

| 지도 | 만들어야 할 구조 | 필요한 검수 |
|---|---|---|
|VAL_CORRIDOR_A|여러 목적지가 좁은 공유 통로를 통과|초기위치→모든설비→활성충전소 도달성, 지정자원 사용|
|VAL_BYPASS_A|주 통로 외 연결 가능한 경로 존재|우회거리·연결성·실제사용경로. 현재K=1이므로 자유경로선택 성능과 구분|
|VAL_STATION_A|서비스위치/접근이 한 구역에 집중|설비대기와통로대기 분리, 실제부하 노출|

각지도에서 미리 정한4조건을 평가한다: L06/C4/A1, L10/C1/A1, L13/C1/A4, L13/C4/A4. 좋은조건과 이점이 작을 조건을 함께 남긴다. 새seed5개씩·4정책으로3×4×5×4=240회다. 지도별seed도 서로 다르게 둔다.

지도 간에는 이동거리·접근경로가 달라질 수 있다. 변경점을 명시하고 정책 비교는 같은지도 안에서 한다. 지도구조 효과를 거리 효과와 완전히 분리했다고 주장하지 않는다.

## 4. 전달받아야 할 입력과 설명

1. **지도:** 노드ID·좌표·층·유형, 엣지ID·연결·방향·폭·길이, 설비/충전소 연결, 단위(1px=0.1m)
2. **초기상태:** 로봇ID별 위치·층·SOC, 활성충전소·슬롯수, 다층이면 캐빈별 초기층
3. **수요:** UID·도착시각·목적지·적합설비·우선순위·입력납기·처리잡음과 생성seed
4. **개입:** 통로 변경 요청 시각·대상·값·복원 요청, 실제활성시각은 결과로 별도 기록
5. **설계설명:** 바꾸는축·고정값·대조조건·예상병목·확인할지표·기존조건과의차이
6. **검수:** 도달성, 중복/누락UID, 슬롯수/충전속도 의미, 실제주문수, 총면적·거리, 버전/hash

추천 표 형식은 `scenario_id / layout_id / load / slots / arrival_shape / compare_to / fixed_values / primary_metric / scope_limit`다. 실제JSON의 필드명은 구현 시 입력계약에 맞춰 확정한다.

## 5. 현재 분담과 다음 확장

강재민 측은 통로변경 공통제어 오류, CP-SAT 준비 상태, 입력 생성/감사·실행·계측 기반을 먼저 정리한다. 시나리오 담당자는18조건의 수치·대조관계 검토와3개 지도안을 병행한다. 코드/입력 게이트가 끝나기 전에 대규모 시뮬레이션을 시작하지 않는다.

핵심 실험 뒤에 낮은 초기SOC, 긴급 비율·납기여유, 고정 총충전전력, 속도혼합, 다층·승강기, 제한 후 회복을 질문별로 추가한다. 모든 변수를 동시에 바꾸면 어느 요인이 차이를 만들었는지 설명하기 어렵다.

같은3층에서 부하와 캐빈1/2대를 먼저 비교하고, 층수 자체는 총면적 고정 실험을 별도로 둔다. “상층 목적지50%”는 실제층간이동50%를 보장하지 않으며 실제상하행·공차이동·대기는 결과에서 확인한다.

## 6. 팀원에게 부탁할 검토

- 저/기준/고부하가 실제로 서로 다른 혼잡 상태를 만드는지 확인해 달라.
- 충전이 전혀 없는 조건과 대부분이 실패하는 조건이 각각 어떤 역할인지 설명해 달라.
- 새 지도가 기존 격자와 구조적으로 어떻게 다른지 도식과 변경표로 정리해 달라.
- 특정 정책의 결과를 보고 그 정책에 유리하도록 입력을 바꾸지 말고, 필요한 수정은 전체정책 공통 새버전으로 기록해 달라.
- 가정값과 현장근거를 분리해 달라. 현재 모든 수치는 합성연구값이며 실제한국업체 제원이 아니다.

이 문서는 전달용 파일이다. 팀원에게 메시지를 보내거나 입력 작성이 완료됐음을 확인한 기록은 아니다.
