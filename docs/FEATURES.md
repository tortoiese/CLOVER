## 🏭 업체 환경 설정 방법

### 방법 1: GUI 설정 에디터
1. 툴바의 **[⚙ 공장 설정]** 클릭
2. 팔레트에서 설비를 드래그 & 드롭으로 배치
3. 클릭하여 속성(좌표, 처리시간, 충전 슬롯 수 등) 편집
4. **[🧭 경로 편집]** 모드: 빈 곳 클릭 = 노드 추가, 노드 두 개 연속 클릭 = 엣지 연결, 우클릭 = 삭제 (벽에 막힌 엣지는 빨간 점선)
5. **[🤖 로봇 관리]** 탭에서 로봇 추가/삭제·파라미터 설정, 상단에서 업체별 프리셋 저장/불러오기
6. **[저장]** → 시뮬레이터에 즉시 반영 (무중단 핫리로드)

### 방법 2: DB 직접 수정
외부 시스템(MES/WMS)에서 `factory_config.db`의 테이블을 INSERT/UPDATE하고 **`config_changelog`에 변경 이력 행을 함께 남기면**, ConfigWatcher가 1초 내 감지하여 시뮬레이터에 반영합니다. (`DBManager` / `FactoryService`를 통해 쓰면 이력은 자동으로 기록됩니다.)

### 방법 3: AI 관제 콘솔
```
> 충전소 하나 더 추가해 위치 (400, 300)
> WS-03 위치를 (200, 150)으로 옮겨줘
> 로봇 2대 더 투입해
```

## 🏢 다층 공장 · 3D 건물 · 엘리베이터

### 구성
- 공장은 **최대 6층**까지 설정합니다 (`공장 정보 > 층 수`). 층마다 스테이션·충전소·벽/문/장애물·경로 노드가 따로 있고, 바닥 크기는 모든 층이 같습니다.
- **엘리베이터**는 모든 층의 같은 (x, y)를 관통하는 승강로입니다. 층 사이 이동은 엘리베이터로만 가능합니다.
  - 속성: 라벨, 좌표, 크기, 한 층 이동 시간(기본 4초), 동시 탑승 수(기본 1), 운행 여부
  - 문 개폐 시간은 공장 프로필의 `door_time_sec`(기본 6초)를 씁니다.
- 로봇은 **가장 낮은 층의 충전소 근처(1층 도크)** 에서 출발합니다. 다른 층 작업이면 경로탐색이 엘리베이터를 포함하고, 탑승 대기·캐빈 호출·이동이 시뮬레이션됩니다.
- 층이 다르면 `distance_to_facility()`가 엘리베이터 이동을 환산 거리로 더해 스케줄러가 층간 이동 비용을 고려합니다.

### 3D 건물 개요 → 층 도면
| 조작 | 동작 |
|---|---|
| 층 바닥판 클릭 | 건물이 중앙에서 **왼쪽 위로 줄어들며** 그 층의 도면이 열림 |
| 줄어든 건물에서 다른 층 클릭 / `1F 2F 3F` 버튼 | 도면 층 전환 |
| `↩ 전체 보기` / `Esc` | 건물이 다시 중앙으로 커짐 |
| 건물 드래그 / 더블클릭 | 회전·기울기 / 시점 초기화 |
| 도면 `Ctrl + 휠` | 축척을 **1:25 · 50 · 100 · 200 · 250 · 500 · 1000** 단계로 변경 (격자 1칸이 화면에서 딱 떨어지는 값) |
| 도면 더블클릭 / `맞춤` | 전체가 보이도록 맞춤 |

- 헤더에 `축척 1 : 500`, `격자 1칸 = 5 m (화면 10 mm)`가 표시되고, 도면 왼쪽 아래에 축척 막대(예: `10 m · 1 : 526`)가 붙습니다. 화면 DPI 기준입니다.
- 층이 1개인 공장은 3D 개요 없이 바로 도면이 열립니다.
- 3D 모델은 외부 모델 없이 QPainter 다각형으로 그려 가볍습니다. 스테이션(공정 색), 충전소(기둥), 벽·문·장애물, 엘리베이터 승강로·캐빈, 탑승 중인 로봇을 표시합니다.

### 공장 설정 에디터에서
- 툴바 **편집 층** 콤보로 한 층씩 편집합니다. 엘리베이터는 모든 층에 함께 보입니다.
- 팔레트의 **🛗 엘리베이터**를 끌어다 놓고, 속성 패널에서 값을 바꿉니다. 스테이션·충전소·장애물은 `층` 값을 바꿔 다른 층으로 옮길 수 있습니다.
- 층 수를 늘리면 새 층에 격자 경로망이 자동 생성되고, 줄이면 없어지는 층의 설비 삭제를 확인합니다. **[이 층 격자 경로망 생성]** 은 현재 편집 층만 새로 만듭니다.
- 저장 시 모든 층에 경로 노드가 있어야 하며, 층이 2개 이상인데 운행 가능한 엘리베이터가 없으면 확인 창이 뜹니다.
- 프리셋 **`3층 데모 공장`** 이 기본으로 들어 있어 기존 DB에서도 불러올 수 있습니다.

### 데모 공장 (3층)
| 층 | 스테이션 | 충전소 |
|---|---|---|
| 1F | 조립 A(WS-01), 용접(WS-02) | CS-01 |
| 2F | 도장(WS-03), 검사(WS-04) | CS-02 |
| 3F | 포장(WS-05) | CS-03 |

엘리베이터 `EL-01`이 세 층을 잇습니다. 기본 주문은 제품A(WS-01·03·05), 제품C(WS-03·04)입니다.

## 🚧 물리 제약 시나리오

로봇 크기·통로 폭·교차점·엘리베이터 같은 **물리 변수**를 모델링해 병목을 눈에 보이게 합니다.

| 요소 | 모델 |
|---|---|
| 통로(엣지) 폭 | 폭(m) → 차선 수 = ⌊(폭 − 벽 여유 0.4) ÷ (기준 로봇폭 0.6 + 측면 여유 0.3)⌋. 차선은 SimPy `Resource` |
| 로봇 크기 | 폭·길이(기본 0.6 × 0.8 m). 폭이 큰 로봇은 차선을 더 점유 |
| 교차점 | `node_type="intersection"` 노드는 동시에 1대만 통과 (통과 시간 = 길이 ÷ 속도 + 1초) |
| 엘리베이터 | 동시 탑승 수 제한, 문 개폐 + 층 이동 시간 |
| 노드 용량 | `capacity` 컬럼으로 엘리베이터 노드의 동시 운행 수 지정 (없으면 기본값) |

- 추가 KPI: **통로 대기시간**(`corridor_wait`), **EV 대기시간**(`ev_wait`), **교착 발생**(`deadlock_count`, 통로 대기 120초 초과).
- 기본 데모(통로 폭 5.0m)는 병목 없이 기존과 같은 수치로 동작합니다.

### 레이아웃 × 난이도 프리셋
`database/seed_data.py`의 `build_scenario_config(layout, difficulty, corridor_width)` 로 만들며, 레이아웃 3종은 공장 설정 에디터 프리셋(`physical-corridor / physical-grid / physical-loop`)으로도 들어 있습니다.

| 레이아웃 | 설명 |
|---|---|
| `corridor` 중앙복도형 | 좌/우 스테이션 블록을 중앙 통로 하나로 연결, 충전소 분기점이 교차점 |
| `grid` 격자형 | 1층 기본 구성 + 중앙 교차점, 교차점 인접 통로 폭 조절 |
| `loop` 루프형 | 1층 루프 통로(교차점 1개) + 엘리베이터 EV-01로 연결된 2층 포장 구역 |

| 난이도 | 운영 변수 (물리 레이아웃은 그대로) |
|---|---|
| S1 평시 | 기본 작업률 |
| S2 증속 | 작업률 ×1.8 |
| S3 교란 | 첫 충전소 비활성 |
| S4 증설 | 로봇 +2대 |

`python -m database.seed_data` 로 같은 레이아웃에서 **통로 폭만 줄이면(3.0m → 1.8m → 1.2m)** 완료량이 줄고 통로 대기가 늘어나는 것을 확인할 수 있습니다.

## 🧠 RAG (문서 검색 관제)

등록한 문서와 운영 로그에서 질문과 관련된 **근거를 찾아 출처와 함께 보여 주는** 기능입니다. 시뮬레이터가 상태를 계산하고 스케줄러가 배정하며, RAG가 최적해를 계산하지는 않습니다. 기본은 비활성이고 **로컬 검색(외부 API 호출 없음)** 입니다.

- 입력: MD / TXT / 텍스트 PDF / JSONL → 청크 → ChromaDB → 검색 → 출처 표시
- 관제 콘솔에서 `/검색 …`, `/rag …`, `문서: …` 로 사용. 검색 응답은 제어 조치를 만들지 않습니다.
- 생산 이벤트 DB를 읽기 전용으로 JSONL로 내보내 검색 자료로 등록할 수 있습니다.

| 환경 변수 | 기본값 | 설명 |
|---|---|---|
| `CLOVER_RAG_ENABLED` | `0` | `1`이면 RAG·운영안 비교 활성 |
| `CLOVER_RAG_PROVIDER` | `local` | `local` 또는 OpenAI 연결 어댑터 |
| `CLOVER_RAG_DATA_PATH` | `rag_data/` | 벡터 저장 폴더 |
| `CLOVER_RAG_DOCUMENT_PATH` | 저장소 `README.md` | 처음 등록할 자료 (기본은 저장소 README이므로 README를 고치면 RAG 답변 근거도 바뀜. 상세 문서는 `docs/`에서 따로 등록) |
| `CLOVER_RAG_ALLOW_NETWORK` | `0` | `1`이어야 외부(OpenAI) 요청 허용 |
| `OPENAI_API_KEY` | 없음 | 외부 모델 사용 시 키 (코드·문서에 넣지 않기) |
| `CLOVER_RAG_MIN_SCORE` | `0.15` | 검색 최소 점수 |

```bash
python -m agent.rag.cli ingest <파일|폴더> [--policy]          # 자료 등록 (--policy: 추천 근거 문서)
python -m agent.rag.cli ask "충전 대기 증가 원인" [--dataset-id ...]
python -m agent.rag.cli export-events <db> <out.jsonl> --dataset-id <이름> --origin simulation
python -m agent.rag.cli demo                                    # 합성 로그 데모
```
구축·운영 기준은 [docs/RAG_POLICY.md](RAG_POLICY.md)를 따릅니다 (등록 자료 기준, 답변 규칙, 외부 모델 사용 기준).

## 🧮 운영안 비교 (MILP)

현재 GUI 공장 구성으로 **베이스라인 배정**과 **MILP 배정안**을 같은 조건(주문·도착·난수)에서 반복 실행해 비교합니다. RAG를 켠 상태에서 툴바 **[운영안 비교]** 로 엽니다.

- MILP: SciPy/HiGHS `milp`로 현재 유휴 로봇의 단일 작업 배정을 계산합니다 (다층 공장은 층별 거리·엘리베이터 비용을 반영). 전체 기간 최적성을 증명하지 않습니다.
- 결과: 처리량·대기시간·비용·순이익 차이와 95% 신뢰구간, 추천/보류 의견, 실험 결과 JSON 저장. 비용 모델이 없으면 추천을 보류합니다.
- 비교 실험은 DB와 실행 중인 공장을 변경하지 않습니다.

| 채팅 명령 | 기능 |
|---|---|
| `/최적화 도움말` | 지원 조건·단위·제한 안내 |
| `/조건 기간=120 반복=3` | 비교 조건 설정 (GUI 양식과 동기화) |
| `/최적화` 또는 `비용 줄여줘` | 현재 구성으로 새 비교 실험 |
| `/비교` · `/추천` · `/ROI` · `/근거` | 마지막 결과 표시 · 추천 이유 · 수익 지표 설명 · 운영 기준 문서 검색 |

자세한 사용법·산식·오차 해석: [docs/RAG_GUI_OPTIMIZATION.md](RAG_GUI_OPTIMIZATION.md)

## 💰 ROI (수익성 계산)

대시보드 **💰 ROI 비교** 탭에서 베이스라인과 최적화안의 수익성을 비교합니다.

- 입력 6개: 이동거리 d, 소비효율 e(Wh/m, 기본 0.133), 전력 단가 p(원/Wh, 기본 0.13 = 130원/kWh), 완료 건수 Q, 건당 가치 v(기본 2,000원), 기타 비용(기본 60,000원). **이동거리와 완료 건수는 시뮬레이션이 자동 수집**하고, 나머지는 탭에서 조절합니다.
- 계산: 전력 소비량 E = d × e → 전력 비용 → 총투입비용 → 총매출 → **총순이익 · 건당 순이익 · ROI(%) · 전력 대비 순이익**
- 전력 소비량·총투입비용·총순이익·ROI를 2×2 막대 그래프로 비교합니다 (`utils/roi_chart.py`는 matplotlib Figure/PNG도 생성).
- 기본 비용값은 `config.py`의 fallback이며 기업 데이터 수령 시 교체합니다. (운영안 비교의 비용 모델과 별개의 간이 산식입니다.)

## 📊 성능 지표 (KPI)

| KPI | 설명 |
|---|---|
| Throughput | 단위 시간당 완료 작업 수 |
| Avg Wait Time | 작업 큐 평균 대기시간 |
| Utilization | 로봇 가동률 |
| Charge Wait | 충전 대기 평균시간 |
| Idle Rate | 로봇 유휴율 |
| Battery Efficiency | 충전 1회당 작업 완료 수 |
| Order Fulfillment | 납기 내 완료 주문 비율 |
| Response Time | 긴급 이벤트 대응 시간 |
| Corridor Wait | 통로 차선 대기 평균시간 (물리 제약) |
| EV Wait | 엘리베이터 탑승 대기 평균시간 |
| Deadlock Count | 통로 대기 120초 초과 건수 |
