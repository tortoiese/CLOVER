# RH 구현 검수와 적용 범위

검수일: 2026-10-26. 기준 main: `841af64c2ef4684053d0aadeed0b5fee8df36ec7`.

기본 정책은 기존 `optimized` 가중치 휴리스틱이다. RH-MILP와 RH-CP-SAT은 사용자가 선택하는 추가 정책이다. M0~M3의 구현과 M4의 GUI·경제성·실험·재현·CI 기능을 통합했다. 전체 PRD의 출시 성능 목표가 모두 달성됐다는 판정은 하지 않는다.

## 코드 검수

- 불변 snapshot·공통 정수 모델·두 단계 목적함수, MILP/CP-SAT parity와 독립 경로·자원·에너지 검증을 확인했다.
- prefix 확정 중 예외를 주입해 큐·작업·예약·소유권 롤백을 확인했다. 재계획 경계까지 대기만 실행하면 미래 작업을 배정하지 않는다. 전 구간 보류 해는 대체 실행 대상으로 둔다.
- timeout·의존성 부재·RSS·취소·설비 변경·탑승 중단·지연 해·부분 충전·reset을 검사했다. 모델 최적 상태와 실제 지연 후 실행 상태를 구분한다.
- 경로 캐시는 그래프별 최대 1,024개이며 설정 변경으로 그래프를 새로 만들면 재사용하지 않는다. 휴리스틱 가중치는 바꾸지 않았다.
- Windows CI에서 발견한 ChromaDB/SQLite 파일 잠금을 수정했다. 소유 스레드에서 저장소를 닫고, 작업 스레드 종료 후 GUI 소유 DB를 닫는다. 재개방 시 데이터 보존도 검사했다.
- 실제 비교 화면의 흰 배경·희미한 글씨를 발견해 공통 QSS의 텍스트 창·표 헤더를 수정하고 다시 확인했다.

CI는 PR 커밋마다 다시 실행한다. 위 링크는 Windows 수정 후 커밋의 증거이며 최신 커밋 상태는 PR Checks를 따른다. 로컬 Linux ARM64 Docker에서는 Qt paint 중 native 참조 카운트 종료 오류를 재현했다. Ubuntu x86_64 CI 성공을 ARM64 GUI 승인으로 해석하지 않는다.

GUI는 새 DB·기본 3층, RAG 비활성 5정책 비교·가상 ROI·저장, 두 RH의 완료·계획·예약, 주문 취소·충전기 변경, 고배속·일시정지·reset, 종료·재실행, JSON의 CLI 재생을 검사했다. RH 완료 흐름은 **로봇 1대·2층·단일 캐빈·H=12**의 명시적 프로필이다. 기본 5대 공장의 높은 수락률을 증명한 검수로 보고하지 않는다. 고의 solver 지연·고장·구버전 DB 등은 자동 회귀가 보완한다. 모든 조합을 별도 운영자가 수동 승인한 것은 아니다.

실제 창의 30명령 측정 3회 P95는 **114.1 / 135.3 / 89.4ms**, 정책 활성화 재시작은 **223.1 / 223.7 / 224.3ms**다. 캐시 개선 전에는 부하에 따라 184~363ms와 재시작 약 2.1초가 관측됐다. 최종 측정은 150ms 제안 목표 안이지만 모든 부하 조건의 보장은 아니다.

## 성능 비교

[증거 JSON](rh_benchmark_evidence.json)에 4개 시나리오의 입력·설정·환경·source hash·전체 trace·모든 시드별 스칼라 지표·계획 품질·solver 시간 분포·사전 판정을 포함했다. 원본 전체 export SHA256도 기록했다. 재현 명령은 [사용 가이드](ROLLING_HORIZON.md#재현-가능한-비교)를 따른다.

양 RH는 같은 모델·후보·입력·계산 예산을 쓴다. 정책별 도착/처리 표본을 공통으로 제공하되 계획기에는 관측 전 미래 도착·실제 처리 난수를 주지 않았다. 측정 후 변경된 기존 Python 소스 8개는 파일 핸들 종료 관련이고 Qt 테스트 세션용 `conftest.py`가 추가됐다. 시뮬레이션 결정·모델·휴리스틱·경로 hash는 동일하다. headless 측정 환경과 이후 Qt 고정 환경을 구분한다.

### 별도 검증 시드 100~109: 교대 물류

다음은 시드별 지표의 평균이다. 대기 P95는 생성→시작 관측 표본의 P95이며 미완료와 표본 수도 함께 보고한다.

| 120초, 8초 간격 배치 | 가중치 휴리스틱 | RH-MILP | RH-CP-SAT |
|---|---:|---:|---:|
| 완료 / 미완료 | 29 / 1 | 30 / 0 | 30 / 0 |
| 대기 P95, 초 | 8.235 | 3.981 | 3.476 |
| 대기 표본 수 | 29 | 30 | 30 |
| 납기 내 / 지연 완료 | 15 / 14 | 29.4 / 0.6 | 30 / 0 |
| 수평 이동거리, m | 89.55 | 60.4 | 60.0 |
| 소비 배터리 상대 단위 | 13.313 | 10.546 | 10.506 |
| 실패 실행 | 0/10 | 0/10 | 0/10 |

완료량은 두 RH 모두 +3.448%다. MILP의 시드별 대기 P95 상대 차이 평균은 **-51.758%, paired 95% t 구간 [-64.410%, -39.106%]**, CP-SAT은 **-57.536% [-60.089%, -54.983%]**다. 사전 기준인 완료량 차이 하한 ≥ -5%, 대기 P95 차이 상한 ≤ -10%를 통과했다. MILP 155회 중 152회 OPTIMAL·3회 FEASIBLE, CP-SAT 150회 OPTIMAL이다. 제한 시간의 해를 최적해로 바꿔 표시하지 않았다. 정상 채택률은 각 시드 100%, fallback 0%였다.

240초·10초 간격의 별도 10시드 민감도 검사에서는 모두 48건 완료·미완료 0건이다. 대기 P95 5.481→3.481초, 상대 차이 평균 -36.488% [-36.531%, -36.446%], 지연 완료 24→0건으로 기준을 통과했다. 두 RH 모두 240회 OPTIMAL이다.

이 사례는 먼저 온 작업에 가까운 로봇을 쓰면 다음 작업 배정이 불리해지는 구조다. 공동 배정의 효과를 검증하며 단순 배정에서는 헝가리안 알고리즘도 개선할 수 있다. 충전·교통·캐빈 모델 각각의 독립 효과나 모든 공장의 우위를 뜻하지 않는다.

### 탐색 시드 42~44: 불리한 결과 포함

| 120초, 3시드 평균 | 휴리스틱 | RH-MILP | RH-CP-SAT |
|---|---:|---:|---:|
| 단일 충전 슬롯 완료 | 18.67 | 25.33 | 25.67 |
| 단일 충전 슬롯 대기 P95, 초 | 67.90 | 65.25 | 70.21 |
| 기본 3층 공장 완료 | 21.00 | 14.33 | 14.33 |
| 기본 공장 미완료 | 5.67 | 12.33 | 12.33 |
| 기본 공장 대기 P95, 초 | 41.52 | 56.75 | 51.98 |

충전 슬롯은 완료량이 늘었어도 신뢰구간을 포함한 종합 기준을 통과하지 못했다. 기본 공장은 두 RH 모두 완료량 약 31.7% 감소로 불리했다. 기본 공장 MILP 정상 채택률은 88~93.8%, fallback 6.3~12%; CP-SAT은 94.1~100%, fallback 0~5.9%다. 모든 시드에서 90%/5% 목표를 충족한 결과가 아니다. 수락률 개선이 처리량 개선을 뜻하지도 않는다.

Wh·매출·전기요금은 실측값을 넣지 않아 성능 실험의 비용·ROI는 null이다. GUI의 ROI는 명시적으로 가상 단가를 넣은 산식 검수다.

## PRD 상태와 남은 출시 게이트

| 영역 | 판정 |
|---|---|
| M0 물리, M1 MILP, M2 CP-SAT, M3 교통·단일 캐빈 | 명시한 범위의 구현·자동 회귀 완료 |
| M4 GUI·경제성·실험·재생·CI 기능 | 구현·플랫폼 회귀·native 흐름 검수 완료 |
| 선택형 RH 통합 PR | 기본 정책을 유지하고 제한을 명시해 검토 가능 |
| 전체 PRD 최종 출시 목표 | 미달 항목 존재 |

남은 출시 게이트는 일반 공장 처리량·정상 채택/fallback 개선, 고정 장비의 성능 승인, PRD 제안의 대표 3시나리오×20시드×600초 이상 확대 확인 실험, 별도 운영자의 수동 인수다. 현재 10시드 확인 실험을 확대 프로토콜의 완료라고 세지 않는다. ARM64 Linux GUI·합승 캐빈·전체 도로망 경로 전역 최적화도 승인 범위에 포함하지 않는다. 이 목표들을 통과했다고 주장하거나 기본 정책을 자동 변경하지 않는다.
