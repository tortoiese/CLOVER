# 🤖 Robot Factory Simulator

> **SimPy 기반 멀티로봇 공장 시뮬레이터 + AI 대화형 관제 시스템**  
> IC-PBL 캡스톤 디자인 2 — 클로봇(Clobot) 제안 주제

---

## 📌 프로젝트 개요

제조 현장의 멀티로봇 작업 배정 및 충전 스케줄링을 최적화하는 시뮬레이션 플랫폼입니다.  
납품 업체가 자사 공장 환경(설비 배치, 로봇 수, 충전기 등)을 설정하면 DB에 저장되고, 시뮬레이터에 **실시간 반영**됩니다.  
AI 관제 콘솔을 통해 자연어로 시뮬레이션을 제어하고, 긴급 생산 상황에 자율적으로 대응합니다.

> 📘 **처음 사용하시는 고객(납품 업체) 담당자**는 [제품 사용 설명서](#manual)부터 읽어주세요.

### 핵심 가치
| | Baseline (기존) | 본 솔루션 (최적화) |
|---|---|---|
| 작업 배정 | 라운드로빈(순서대로) | 배터리·거리·큐·납기 가중합 최적 배정 |
| 충전 스케줄링 | 배터리 소진 시 충전 | 예측 기반 선제 충전 + 긴급 시 최소충전 복귀 |
| 설비 변경 대응 | 시뮬레이션 재시작 필요 | DB 핫리로드, 무중단 반영 |
| 긴급 주문 대응 | 수동 재배치 | AI 자율 판단 + 자동 로봇 재배치 |

### 좌측 — 공장 시뮬레이터 시각화
- 2D 공장 바닥 뷰 (QGraphicsScene)
- 작업 스테이션, 충전소, 로봇, 벽/문/장애물을 DB 기반으로 동적 렌더링
- 로봇 상태별 색상: 이동(파랑), 작업(초록), 충전(노랑), 대기(회색), 고장(빨강), 긴급배정(주황 깜빡임)
- 로봇 배터리 잔량 바 + 이동 경로 점선 애니메이션

### 중앙 — AI 대화형 관제 콘솔
- 자연어 명령으로 시뮬레이션 제어 (로봇 추가/충전/배속 변경 등)
- 긴급 주문 투입, 설비 고장 처리, 병목 분석 등
- AI가 긴급 상황 자동 감지 → 자율 대응 → 결과 보고

### 우측 — 성능 대시보드
- 8개 KPI 카드 (Baseline 대비 증감률 표시)
- 7개 탭 차트: Throughput 비교, 로봇 상태 타임라인, 대기열 추이, 배터리 추이, 레이더 비교, 주문 진행률, 이벤트 타임라인

### 스레드 구성
| 스레드 | 역할 |
|---|---|
| 메인 (Qt GUI) | 화면 렌더링, 사용자 입력 |
| SimWorker | SimPy 실행 — Baseline·최적화 엔진을 같은 시드로 나란히 돌려 KPI 동시 비교 |
| ConfigWatcher | `config_changelog` 1초 폴링 → 설정 핫리로드 |
| ProductionEventWatcher | `production_events` 1초 폴링 → AI 자율 대응 |

스레드 간 통신은 모두 Qt Signal/Slot으로 한다. 툴바의 스케줄러 선택은 **화면 표시·AI 조치 대상 엔진**을 바꾸며, 두 엔진은 항상 함께 실행된다.

## ⚙️ 설치 & 실행

### 요구사항
- Python 3.11+
- 운영체제: Windows / macOS / Linux

### 설치
```bash
git clone <repo-url>
cd CLOVER/robot_factory_sim
pip install -r requirements.txt
```
> Windows에서 PySide6 설치가 긴 경로 문제(`OSError: [Errno 2] ...`)로 실패하면 Windows 긴 경로 지원을 켜거나, 경로가 짧은 가상환경(예: `C:\venv`)에 설치하세요.

### 실행
```bash
python main.py
```
- 최초 실행 시 `factory_config.db`가 자동 생성되고 기본 공장 구성(스테이션 5개, 충전소 2개, 로봇 5대)이 삽입됩니다.
- GUI 창이 열리면 **[▶ 시작]** 버튼으로 시뮬레이션과 DB 감시(ConfigWatcher / ProductionEventWatcher)를 시작하세요.
- 다른 DB 파일을 쓰려면 환경변수 `ROBOT_FACTORY_DB`에 경로를 지정합니다.

### GUI 없이 테스트
```bash
python -m simulation.engine          # Baseline vs 최적화 KPI 비교 (headless)
python -m agent.mock_agent           # 자연어 명령 해석 확인
python -m simulation.factory_service # :memory: DB로 서비스 동작 확인
```

## 🏭 업체 환경 설정 방법

### 방법 1: GUI 설정 에디터
1. 툴바의 **[⚙ 공장 설정]** 클릭
2. 팔레트에서 설비를 드래그 & 드롭으로 배치
3. 클릭하여 속성(좌표, 처리시간, 충전 슬롯 수 등) 편집
4. **[🧭 경로 편집]** 모드: 빈 곳 클릭 = 노드 추가, 노드 두 개 연속 클릭 = 엣지 연결, 우클릭 = 삭제 (벽에 막힌 엣지는 빨간 점선)
5. **[🤖 로봇 관리]** 탭에서 로봇 추가/삭제·파라미터 설정, 상단에서 업체별 프리셋 저장/불러오기
6. **[저장]** → 시뮬레이터에 즉시 반영 (무중단 핫리로드)

### 방법 2: DB 직접 수정
외부 시스템(MES/WMS)에서 `factory_config.db`의 테이블을 INSERT/UPDATE하고 **`config_changelog`에 변경 이력 행을 함께 남기면**, ConfigWatcher가 1초 내 감지하여 시뮬레이터에 반영합니다. (`DBManager` / `FactoryService`를 통해 쓰면 이력은 자동으로 기록됩니다.)

### 방법 3: AI 관제 콘솔
```
> 충전소 하나 더 추가해 위치 (400, 300)
> WS-03 위치를 (200, 150)으로 옮겨줘
> 로봇 2대 더 투입해
```

## 📊 성능 지표 (KPI)

| KPI | 설명 |
|---|---|
| Throughput | 단위 시간당 완료 작업 수 |

### 1. 이 제품으로 할 수 있는 일

| 목적 | 이렇게 사용하세요 |
|---|---|
| **로봇 몇 대가 필요한지** 알고 싶다 | 로봇 수를 바꿔가며 처리량·대기시간·가동률을 비교 |

| **설비 배치 변경** 효과를 미리 보고 싶다 | 설정 에디터에서 설비를 옮기고 저장 → 가동 중 즉시 반영 |
| **긴급 주문이 들어오면** 납기를 맞출 수 있는지 | 긴급 주문 투입 → AI가 로봇을 재배치하고 예상 소요시간 보고 |
| **설비 고장 시 영향**을 알고 싶다 | 설비를 고장 처리 → 대체 설비 재배정, 납기 재계산 보고 |
| **최적화 스케줄링의 효과**를 수치로 보여주고 싶다 | 같은 조건에서 기존 방식(Baseline)과 동시에 돌려 8개 KPI 비교 |

> 💡 시뮬레이터는 실제 로봇을 움직이지 않습니다. 공장을 가상으로 재현해 **결정을 내리기 전에 결과를 미리 확인**하는 도구입니다.

### 2. 5분 빠른 시작

1. **실행**: `python main.py` (설치는 위 **⚙️ 설치 & 실행** 참고)
   - 처음 실행하면 데모 공장(작업 스테이션 5개, 충전소 2개, 로봇 5대, 진행 중 주문 2건)이 자동으로 만들어집니다.
2. **[▶ 시작]** 클릭 → 로봇들이 움직이기 시작합니다.
3. 툴바의 **배속**을 `10x`로 올리면 결과를 빨리 볼 수 있습니다.
4. 중앙 콘솔의 빠른 명령 **[긴급 주문]** 클릭 → 몇 초 안에 AI가 긴급 대응 보고를 올리고, 화면 하단에 빨간 배너가 뜹니다.
5. 오른쪽 대시보드에서 KPI 카드와 그래프를 확인합니다. 카드의 **초록 ▲▼는 개선, 빨강은 악화**입니다.
6. 우리 공장으로 바꾸려면 **[⚙ 공장 설정]** → 설비 배치 → **[저장]** ([4장](#m4) 참고)

### 3. 화면 읽는 법

#### 3-1. 상단 툴바

| 버튼 | 기능 |
|---|---|
| **▶ 시작** | 시뮬레이션 실행 + DB 변경 감시 시작 (이후 외부 시스템의 DB 변경·긴급 이벤트가 자동 반영됨) |
| **⏸ 일시정지** | 시간을 멈춤. 다시 ▶ 시작으로 이어서 진행 |
| **⏹ 정지** | 멈추고 **시간 0의 초기 상태로 되돌림** |
| **⏩ 배속** | 1x / 2x / 5x / 10x. `1x`는 현실 1초 = 시뮬레이션 1초 |
| **↺ 리셋** | DB의 최신 공장 구성으로 처음부터 다시 시작 (실행/정지 상태는 유지) |
| **스케줄러** | `최적화` / `Baseline` 중 화면에 보여줄 방식 선택. **두 방식은 항상 동시에 돌고 있으므로** 바꿔도 결과가 초기화되지 않음 |
| **⚙ 공장 설정** | 설비·로봇·경로 편집기 열기 |
| **📋 주문 관리** | 생산 주문 조회/추가/취소 |
| **DB: ● 연결됨** | 초록 = 정상, 빨강 = DB 파일에 접근 불가 |

#### 3-2. 왼쪽 — 공장 시각화

상단 정보 칩: `Sim T+시:분:초`(시뮬레이션 경과) · `경과 분:초 · 배속`(실제 경과) · 활성 주문 수 · 대기 작업 수 · 현재 모드.
**경로망** 체크를 끄면 파란 주행 경로 격자가 숨겨집니다.

**로봇** (원형)
| 표시 | 의미 |
|---|---|
| 원 안 채움 색 | 상태 — 🔵 이동 · 🟢 작업(작업대기 포함) · 🟡 충전(충전대기 포함) · ⚪ 대기 · 🔴 고장(방전) |
| 🟠 **주황색 깜빡임** | AI가 긴급 주문에 배정한 로봇 |
| 테두리 색 | 로봇 고유 색 (배터리 그래프 선 색과 같음) |
| 원 안 숫자 | 로봇 번호 (`R-03` → `03`) |
| 원 아래 막대 | 배터리 — 초록 60% 이상, 주황 30~60%, 빨강 30% 미만 |
| 원 위 글자 | 처리 중인 주문 번호 (`ORD-` 생략) |
| 점선 | 앞으로 이동할 경로 |

마우스를 올리면 상태·배터리·목표 설비·완료 작업 수가 표시됩니다.

**작업 스테이션** (사각형)
| 표시 | 의미 |
|---|---|
| 채움 색 | 공정 종류 (조립·용접·도장·검사·포장·가공) |
| `Q2 · P5` | Q = 스테이션 앞에서 기다리는 로봇 수, P = 아직 로봇이 배정되지 않은 작업 수 |
| 하단 초록 막대 | 설비 가동률 |
| 초록 빛남 | 지금 작업 중 |
| 🟠 **주황 점선 테두리** + `전용 …` | 긴급 주문 전용으로 지정된 설비 |
| ❌ 회색 + 빨간 X | 고장/비활성 |

**충전소** (⚡): 아래 숫자 `1/2 +3` = 슬롯 2개 중 1개 사용 중, 3대 대기.
**벽**(회색 실선) · **문**(청록 점선, 통과 가능) · **장애물**(빗금 사각형) — 로봇은 벽과 장애물을 통과하지 못하고 문으로만 지나갑니다.

#### 3-3. 가운데 — AI 관제 콘솔

- 입력창에 한국어로 지시하면 AI가 답하고 실행합니다 ([6장](#m6)).
- 입력창 위 **빠른 명령 버튼**: 현재 상태 · 효율 분석 · 병목 · 주문 현황 · 납기 위험 · 긴급 주문(예시).
- 말풍선 구분: **파랑(오른쪽)** = 내가 보낸 명령, **어두운 칸(왼쪽)** = AI 답변, **점선 칸(가운데)** = 시스템 알림(설정 반영, 조치 결과 등).
- AI 답변 테두리가 **주황**이면 경고, **빨강**이면 긴급입니다. 제목 옆 **빨간 숫자 뱃지**는 확인하지 않은 경고 수이며, 입력창을 누르면 사라집니다.

#### 3-4. 오른쪽 — 성능 대시보드

**KPI 카드 8개**: 큰 숫자는 현재 선택한 방식의 값, 아래 줄은 다른 방식 대비 변화율입니다.
예) 최적화 모드에서 `▲ 45.0% vs Baseline`이 초록이면 "기존 방식보다 45% 좋아짐".
값이 `—`이면 아직 계산할 데이터가 없는 것입니다 (예: 완료된 주문이 없으면 주문 달성률은 `—`).

**그래프 탭 7개**

| 탭 | 보는 법 |
|---|---|
| Throughput | 파란 선(최적화)과 회색 선(Baseline)의 분당 처리량. 위에 있을수록 좋음 |
| 로봇 타임라인 | 최근 5분간 로봇별 상태 색 띠. **주황 테두리** 구간은 긴급 배정. 회색·노랑이 길면 놀거나 충전만 하는 로봇 |
| 대기열 | 스테이션별 대기 작업을 쌓은 그래프. 한 색이 계속 두꺼워지면 그 설비가 병목 |
| 배터리 | 로봇별 배터리 추이. 0 근처까지 떨어지는 로봇이 있으면 충전 정책/충전소 부족 신호 |
| KPI 레이더 | 8개 지표를 두 방식끼리 상대 점수(좋은 쪽 = 바깥)로 비교. 면적이 넓을수록 우수 |
| 주문 진행 | 주문별 막대: 진한 부분 = 지금까지 경과, 옅은 점선 부분 = 남은 예상 소요, **빨간 세로선 = 납기**. 막대 끝이 빨간 선을 넘으면 납기 위험(⚠) |
| 이벤트 | 🔴 긴급 · ⚙ 설정 변경 · ✅ 완료/복구 · ⚫ 고장 · ℹ 정보를 시간순으로 표시. 점에 마우스를 올리면 내용 표시 |

#### 3-5. 하단 긴급 알림 배너

긴급(빨강)·경고(주황) 상황에서 아래에서 올라옵니다. **배너를 클릭하면 콘솔로 이동해 AI 대응 보고**를 볼 수 있고, `✕` 또는 20초 후 자동으로 닫힙니다. 여러 건이 겹치면 `(+2건)`처럼 표시됩니다.

### 4. 우리 공장 구성하기 (공장 설정 에디터)

툴바 **[⚙ 공장 설정]** 을 누르면 편집 창이 열립니다. **[저장]을 누르기 전까지는 시뮬레이션에 영향이 없으니** 마음껏 편집하셔도 됩니다.

#### 4-1. 좌표와 단위
- 화면 좌표 단위는 **px**이며 **1px = 0.1m** 입니다 (기본 바닥 800×600px = 80m×60m).
- 좌상단이 (0, 0), 오른쪽이 X+, 아래쪽이 Y+ 입니다.
- 설비 좌표는 **중심점** 기준입니다.

#### 4-2. 편집 순서 (권장)
1. **공장 정보** (오른쪽 위): 공장 이름, 바닥 너비·높이, 격자 크기 입력
2. **설비 배치**: 왼쪽 팔레트에서 `작업 스테이션`, `충전소`, `벽`, `문`, `장애물`을 바닥으로 **끌어다 놓기**
   - 놓은 뒤 끌어서 위치 조정 (`격자 스냅`이 켜져 있으면 격자 절반 간격으로 맞춰짐)
3. **속성 편집**: 설비를 클릭하면 오른쪽 **선택 항목 속성**에서 수정

   | 설비 | 편집 항목 |
   |---|---|
   | 작업 스테이션 | 라벨, 좌표, 크기, 공정 종류, 평균 처리시간(초), 처리시간 표준편차, 가동 여부 |
   | 충전소 | 좌표, 충전 슬롯 수(동시 충전 대수), 충전 속도(초당 배터리 %), 가동 여부 |
   | 벽/문/장애물 | 종류, 시작점(X1,Y1)·끝점(X2,Y2), 통과 가능 여부, 라벨 |

4. **주행 경로 만들기** — 로봇은 **경로망(노드와 엣지) 위로만** 이동합니다.
   - 가장 쉬운 방법: **[격자 경로망 자동 생성]** → 바닥 전체에 격자형 경로가 깔립니다 (기존 경로는 삭제됨).
   - 직접 그리기: **[🧭 경로 편집]** 모드에서 빈 곳 클릭 = 노드 추가, 노드 두 개를 차례로 클릭 = 연결선(엣지) 생성.
   - **빨간 점선 엣지**는 벽/장애물에 막혀 사용할 수 없는 길입니다. 문을 그 위에 두면 통과할 수 있습니다.
   - **초록 노드**는 설비와 연결된 노드입니다. 저장할 때 각 설비는 가장 가까운 노드에 자동 연결됩니다. 설비 가까이에 노드가 있는지 확인하세요.
5. **로봇 설정**: 상단 **[🤖 로봇 관리]** 탭

   | 항목 | 설명 | 기본값 |
   |---|---|---|
   | 종류 | 표시용 (AGV, AMR 등) | AGV |
   | 배터리 용량 | 배터리 최대량 | 100 |
   | 속도 | m/s | 2.0 |
   | 소모율 | 1m 이동당 배터리 소모량 | 0.5 |
   | 충전 임계치 | 이 %보다 낮으면 충전하러 감 | 20% |
   | 가동 | 체크 해제 시 시뮬레이션에서 제외 | ✔ |

6. **[💾 저장]** → 1초 안에 가동 중인 시뮬레이션에 반영되고, 콘솔에 `⚙ 설정 핫리로드 완료: …`가 표시됩니다.

#### 4-3. 저장 시 실제로 일어나는 일 (무중단 반영)
| 변경 | 시뮬레이션 반영 방식 |
|---|---|
| 설비 추가 | 즉시 작업 배정 대상에 포함 |
| 설비 삭제·비활성 | 그 설비의 대기/진행 작업을 **같은 공정의 다른 설비**로 자동 재배정 (없으면 가용 설비로 분산) |
| 설비·벽·문 위치 변경 | 경로를 다시 계산하고, 이동 중인 로봇은 새 경로로 우회 |
| 로봇 추가 | 충전소 근처에 새 로봇 투입 |
| 로봇 삭제·가동 해제 | 하던 작업을 반납하고 퇴역 |
| 처리시간·충전속도 등 수치 | 멈춤 없이 즉시 적용 |

#### 4-4. 프리셋 (업체·라인별 구성 저장)
- **[현재 구성 저장]**: 지금 편집 중인 구성을 이름을 붙여 보관 (예: `A사 1공장`, `증설안-로봇8대`)
- **불러오기**: 프리셋을 에디터로 가져옵니다. **[저장]을 눌러야 실제 시뮬레이션에 적용**됩니다.
- 배치안 여러 개를 프리셋으로 만들어 두고 번갈아 적용하면 비교가 쉽습니다.

> ⚠ 저장 조건: 작업 스테이션 1개 이상, 경로 노드 1개 이상이 있어야 합니다. 저장하지 않고 창을 닫으면 확인 창이 뜹니다. **[DB에서 다시 불러오기]** 로 편집 전 상태로 되돌릴 수 있습니다.

### 5. 생산 주문 관리

툴바 **[📋 주문 관리]** 에서 주문을 조회·추가·취소합니다 (목록은 2초마다 자동 갱신).

#### 5-1. 주문 추가
| 항목 | 설명 |
|---|---|
| 제품 | 제품명 (예: 제품A) |
| 수량 | 생산 수량. **1개 = 로봇 작업 1회**(설비 한 곳에서 1회 가공) |
| 우선순위 | `critical`(긴급) > `high` > `normal` > `low` |
| 납기 | 지금으로부터 몇 시간 뒤인지 (0 = 납기 없음). **시뮬레이션 시계 기준** |
| 스테이션 | 이 주문을 처리할 설비. 아무것도 체크하지 않으면 전체 설비 사용 |

- `critical`로 등록하면 **AI 긴급 대응이 자동으로 시작**됩니다 ([7장](#m7)).
- 주문과 별개로, 공장에는 일정 빈도로 일반 작업(백그라운드 작업)이 계속 들어옵니다. 빈도는 콘솔에서 `작업 생성 빈도 높여줘/낮춰줘`로 조절합니다.

#### 5-2. 주문 상태
| 상태 | 의미 |
|---|---|
| pending | 등록됨, 아직 작업 시작 전 |
| in_progress | 생산 중 (완료 수량·진행률 표시) |
| completed | 전량 완료 |
| cancelled | 취소됨 |

#### 5-3. 수량 변경·취소
목록에서 주문을 선택하고 **[선택 주문 수량 변경]** 또는 **[선택 주문 취소]**. 수량을 줄이거나 취소하면 AI가 남는 로봇을 대기시키고 배터리를 미리 충전합니다.

> 🕒 **시뮬레이션 시계**: 시뮬레이션이 시작(또는 정지·리셋)된 시각부터 `시뮬레이션 경과 시간`만큼 흐른 시각입니다. 10x 배속이면 실제 6분에 시뮬레이션 1시간이 지나므로 **납기도 시뮬레이션 시간으로 계산**됩니다.

### 6. AI 관제 콘솔 명령어

문장을 완벽하게 맞출 필요는 없습니다. 아래 **핵심 단어**가 들어가면 인식합니다. `도움말`을 입력하면 명령 목록을 보여줍니다.

#### 6-1. 상태 조회·분석
| 입력 예시 | 결과 | 핵심 단어 |
|---|---|---|
| `현재 상태 알려줘` | 로봇 상태별 대수, 평균 배터리, 저전력 로봇, 대기 작업, 처리량 | 상태 / 현황 / 요약 |
| `현재 효율 분석해줘` | 8개 KPI를 두 방식끼리 비교, 개선·악화 표시 | 효율 / 분석 / KPI |
| `지금 가장 병목인 구간이 어디야?` | 부하 상위 3개 설비, 충전 대기, 권장 조치 | 병목 |
| `현재 주문 현황 보여줘` | 주문별 진행률, 예상 소요, 남은 납기, 위험 여부 | 주문 + 현황/보여/목록 |
| `납기 위험 주문 있어?` | 예상 소요가 남은 시간을 넘는 주문 목록 | 납기 + 위험/임박 |

#### 6-2. 시뮬레이션 제어
| 입력 예시 | 결과 |
|---|---|
| `배속 5배로` | 배속 변경 (1·2·5·10 중 가장 가까운 값) |
| `작업 생성 빈도 높여줘` / `낮춰줘` | 일반 작업 도착 빈도 1.5배 / 2/3배 |
| `스케줄링 최적화 모드로 전환` / `baseline 모드로 전환` | 화면 표시·AI 조치 대상 방식 변경 |
| `R-02 충전해` | 해당 로봇을 하던 일을 멈추고 충전하러 보냄 |
| `최소충전 모드 켜줘` / `꺼줘` | 충전 목표를 50%로 낮춰 로봇을 빨리 현장 복귀시킴 |

#### 6-3. 공장 구성 변경 (DB에 저장되고 즉시 반영)
| 입력 예시 | 결과 |
|---|---|
| `로봇 3대 추가해줘` | 기존 로봇과 같은 사양으로 추가 (한 번에 최대 20대) |
| `충전소 하나 더 추가해 위치 (400, 300)` | 해당 좌표에 충전소 설치 (`3슬롯`처럼 슬롯 수 지정 가능) |
| `WS-03 위치를 (200, 150)으로 옮겨줘` | 설비 이동 + 경로 재계산 |
| `문 위치를 (500, 0)-(500, 100)으로 옮겨` | 첫 번째 문을 해당 선분으로 이동 (`벽`도 동일) |
| `WS-03 고장 처리해` / `WS-03 복구해` | 설비 비활성화(작업 재배정) / 재가동 |

#### 6-4. 주문
| 입력 예시 | 결과 |
|---|---|
| `긴급 주문 넣어줘: 제품A 300개, 2시간 내` | critical 주문 등록 → AI 긴급 대응 |
| `주문 추가해줘: 제품C 50개, 90분 내, WS-01 WS-02` | normal 주문 (스테이션 지정 가능, `우선`이 들어가면 high) |
| `ORD-2026-0003 주문 취소해` | 주문 취소 |

> ⚠ 좌표는 반드시 `(x, y)` 괄호 형식으로, 수량은 `○○개`, 납기는 `○시간`/`○분`으로 적어주세요. 로봇 번호는 `R-2`, `r02`처럼 적어도 됩니다.

### 7. 긴급 상황 자동 대응

긴급 상황은 **사람이 명령하지 않아도** 시스템이 감지하고 AI가 스스로 조치한 뒤 콘솔에 보고합니다. (감지는 [▶ 시작] 이후 동작)

| 상황 | 감지 조건 | AI 자동 조치 |
|---|---|---|
| 🔴 **긴급 주문** | `critical` 주문 등록 | 납기에 맞출 로봇 수 계산 → ① 대기 로봇 투입 ② 부족하면 충전 중(배터리 50% 이상) 로봇 긴급 복귀 ③ 그래도 부족하면 일반 작업 중인 로봇 선점 · 해당 제품 설비 최대 2곳을 **전용 전환** · 납기가 빠듯하면 최소충전 모드 ON |
| 🟠 **납기 임박** | 남은 시간 < 예상 소요 × 1.3 (5초마다 점검) | 대기 로봇 최대 3대 + 충전 로봇 최대 2대 투입, 우선순위를 `high`로 상향, 설비 1곳 우선 배정 |
| 🟡 **생산량 급증** | 진행 중 주문 잔량 합계 > 로봇 1대당 60개 | 최소충전 모드 ON, 충전 중 로봇 복귀, 필요한 추가 로봇 대수 권고 |
| 🔵 **주문 취소/감소** | 주문 취소 또는 수량 감소 | 남는 로봇 대기, 배터리 80% 미만 대기 로봇 선충전, 긴급 주문이 없으면 최소충전 모드 해제 |
| ⚫ **설비 고장** | 설비가 비활성으로 바뀜 | 작업을 대체 설비로 재배정, 영향받는 주문의 납기 재계산 보고 |
| ✅ **완료/복구** | 주문 완료, 설비 재가동 | 결과 보고, 긴급 주문 종료 시 전용 설비·긴급 배정 해제 |

**AI 보고 예시**
```
🚨 긴급 주문 감지: ORD-2026-0042
├ 제품: 제품B, 수량: 500개, 납기: 2.0시간
├ 현재 가용 로봇: R-01, R-04, R-07 (3대)
├ 예상 소요시간: 2.5시간 (로봇 3대 기준)
⚠ 납기 초과 위험!

[자동 조치 실행 중]
✅ R-03(충전 중 78%) 긴급 복귀 → 제품B 라인 투입
✅ R-06(저우선순위 작업) 선점 → 제품B 라인 전환
✅ WS-02, WS-05 우선순위 → 제품B 전용 전환

조치 후 예상 소요시간: 1.7시간 ✅ 납기 충족 가능
```
AI 보고 직후 콘솔에 `✅ 자동 조치 완료: …` 시스템 알림이 뜨면 **실제로 실행된 조치**입니다. 보고와 실제 조치가 다르면(예: 복귀시키려던 로봇이 이미 출발함) 시스템 알림 쪽이 정확합니다.

**배터리 방전**: 이동 중 배터리가 0이 되면 로봇이 🔴 고장 상태로 멈추고, 60초 뒤 구조되어 15% 배터리로 충전소로 갑니다. 방전이 자주 보이면 충전 임계치를 올리거나 충전소를 늘리세요.

### 8. Baseline vs 최적화 비교 결과 해석

시뮬레이터는 **같은 공장·같은 주문·같은 작업 도착 순서**로 두 방식을 항상 동시에 실행합니다. 따라서 차이는 순수하게 **배정·충전 방식의 차이**입니다.

| 구분 | Baseline (기존 방식) | 최적화 (본 솔루션) |
|---|---|---|
| 작업 배정 | 들어온 순서대로, 로봇 순번대로 | 거리·배터리·설비 대기열·우선순위·납기를 점수화해 가장 적합한 로봇·설비에 배정 |
| 충전 시점 | 배터리가 임계치(기본 20%) 아래일 때만 | 임계치 + **다음 작업을 끝내고 복귀할 배터리가 부족하면 미리 충전** + 할 일 없을 때 60% 미만이면 틈새 충전 |
| 충전 목표 | 항상 100% | 평상시 90%, 작업 적체 시 75%, 긴급 시 50% |
| 충전소 선택 | 가장 가까운 곳 | 이동시간 + 예상 대기시간이 가장 짧은 곳 |
| 긴급 작업 | 순서대로 처리 | 우선 배정 + 2초 이상 기다리면 일반 작업 로봇 선점 |
| AI 자동 조치 | 받지 않음 (수동 운영 가정) | 받음 |

> AI 자동 조치와 콘솔 명령은 **현재 화면에 보이는 방식**에만 적용됩니다. 기본 설정(최적화 표시)에서는 Baseline이 "AI 없이 기존 방식으로 운영했을 때"를 나타냅니다.

**KPI 해석 팁**
| KPI | 좋은 방향 | 해석 |
|---|---|---|
| 처리량 (건/분) | ↑ | 최근 2분간 분당 완료 작업 수. 가장 중요한 생산성 지표 |
| 평균 대기시간 (s) | ↓ | 작업 생성부터 설비에서 가공이 시작될 때까지 걸린 시간 |
| 로봇 가동률 (%) | ↑ | 로봇이 이동·작업·작업대기한 시간 비율 |
| 충전 대기시간 (s) | ↓ | 충전소 앞에서 기다린 평균 시간. 크면 충전소 부족 |
| 유휴율 (%) | ↓ | 할 일 없이 대기한 시간 비율 |
| 배터리 효율 (건/회) | ↑ | 충전 1회당 완료 작업 수 |
| 주문 달성률 (%) | ↑ | 완료된 주문 중 납기 내 완료 비율 |
| 긴급 대응시간 (s) | ↓ | 긴급 주문 감지부터 첫 로봇 배정까지 걸린 시간 |

> ⚠ **가동률·유휴율은 처리량과 함께 보세요.** 최적화 방식은 같은 일을 더 짧은 이동으로 끝내므로 처리량이 같거나 높으면서도 가동률이 낮게(유휴율이 높게) 나올 수 있습니다. 이 경우는 **로봇에 여유가 생긴 것**이므로 로봇 대수를 줄이거나 더 많은 주문을 받을 수 있다는 뜻입니다.
>
> 시뮬레이션 초반(수 분)에는 값이 크게 흔들립니다. 판단은 **10배속으로 최소 시뮬레이션 30분 이상** 돌린 뒤에 하는 것을 권장합니다.

### 9. 외부 시스템(MES/WMS) 연동

모든 설정과 주문은 SQLite 파일 `robot_factory_sim/factory_config.db` 하나에 저장됩니다. 외부 시스템이 이 파일에 직접 쓰면 시뮬레이터가 감지합니다.

| 테이블 | 내용 | 반영 방식 |
|---|---|---|
| `factory_profile` | 공장 이름, 바닥 크기, 격자 | ① |
| `work_stations` | 작업 스테이션 | ① |
| `charging_stations` | 충전소 | ① |
| `robots` | 로봇 | ① |
| `obstacles` | 벽(`wall`)/문(`door`)/장애물(`obstacle`) | ① |
| `path_nodes`, `path_edges` | 주행 경로망 | ① |
| `production_orders` | 생산 주문 | ② |
| `production_events` | 긴급 이벤트 (AI가 처리) | ③ |

① **설정 테이블**: 행을 바꾼 뒤 **`config_changelog`에 한 줄을 추가해야** 1초 안에 반영됩니다.
```sql
UPDATE work_stations SET is_active = 0 WHERE id = 'WS-03';
INSERT INTO config_changelog (table_name, record_id, change_type, changed_by)
VALUES ('work_stations', 'WS-03', 'UPDATE', 'mes');
```
- `changed_by`에는 시스템 이름(예: `mes`)을 적으세요. `simulation`, `event_watcher`는 시뮬레이터 내부용이라 **무시됩니다**.
- 좌표 단위는 px(1px = 0.1m), 설비 좌표는 중심점, `is_active`·`is_passable`은 0/1.

② **주문**: `production_orders`에 INSERT만 하면 1초 안에 반영됩니다 (`config_changelog` 불필요).
```sql
INSERT INTO production_orders (order_id, product_type, quantity, priority, deadline, required_stations, created_at)
VALUES ('MES-0001', '제품A', 200, 'critical', '2026-10-01 14:00:00', '["WS-01","WS-02"]', '2026-10-01 12:00:00');
```
- `priority`: `critical` / `high` / `normal` / `low`
- `deadline`: `YYYY-MM-DD HH:MM:SS` — **시뮬레이션 시계 기준** (5-3 참고)
- `required_stations`: JSON 배열 문자열, 비우면 전체 설비
- `critical` 주문은 시뮬레이터가 감지해 긴급 이벤트를 자동 생성하므로, 따로 `production_events`에 넣을 필요가 없습니다.

③ **이벤트**: 외부에서 직접 긴급 이벤트를 알리려면 `production_events`에 `event_type`(`critical_order`, `deadline_risk`, `demand_surge`, `order_cancelled`, `equipment_failure` 등)과 `payload`(JSON)를 INSERT합니다. `is_processed`가 0인 행을 1초마다 읽어 AI가 처리합니다.

> 🔒 DB 파일에 개인정보를 넣지 마세요. 외부 연동 중에는 DB 파일을 백업해 두는 것을 권장합니다.

### 10. 문제 해결 (FAQ)

| 증상 | 원인 / 해결 |
|---|---|
| 로봇이 전혀 움직이지 않음 | **[▶ 시작]** 을 눌렀는지 확인. 누른 뒤에도 그대로면 대기 작업이 없거나 설비가 경로망에 연결되지 않은 것 — 설정 에디터에서 설비 근처에 노드가 있는지 확인 |
| 콘솔에 `○○ → WS-0X 경로 없음` 경고 | 벽/장애물 때문에 그 설비로 가는 길이 없음. 에디터에서 빨간 점선 엣지를 확인하고 문을 추가하거나 경로를 다시 연결 |
| 설정을 저장했는데 화면이 안 바뀜 | 콘솔 창의 `⚙ 설정 핫리로드 완료` 알림을 확인하세요. 알림이 없으면 **[↺ 리셋]** 으로 DB 최신 구성으로 다시 시작 |
| 외부에서 DB를 고쳤는데 반영 안 됨 | 설정 테이블은 `config_changelog` 행이 필요하고, **[▶ 시작] 이후**의 변경만 감지됩니다. 시작 전에 바꿨다면 **[↺ 리셋]** ([9장](#m9)) |
| 긴급 주문을 넣었는데 AI가 반응하지 않음 | [▶ 시작] 전에는 이벤트 감시가 동작하지 않습니다. 시작하면 쌓여 있던 이벤트부터 처리합니다 |
| 로봇이 자주 🔴 고장(방전) | 충전 임계치를 올리거나(예: 30%), 소모율을 확인하거나, 충전소를 동선 가까이 추가 |
| 충전 대기시간이 김 | 충전 슬롯 수를 늘리거나 충전소를 추가 (`충전소 하나 더 추가해 위치 (x, y)`) |
| 특정 설비의 대기열만 계속 늘어남 | 병목입니다. `병목 분석` 후 같은 공정 설비를 추가하거나 처리시간을 줄여 비교 |
| KPI가 `—` 로 표시 | 아직 데이터가 없는 지표입니다 (예: 완료된 주문이 없으면 주문 달성률 없음) |
| 상단 `DB: ● 연결 끊김` | DB 파일이 다른 프로그램에 잠겨 있거나 삭제됨. 외부 프로그램을 닫고 재실행 |
| 처음 상태(데모 공장)로 돌리고 싶음 | 프로그램을 끄고 `factory_config.db`를 삭제(또는 백업 후 이동)한 뒤 다시 실행 |
| 여러 공장 구성을 따로 관리하고 싶음 | 공장별로 프리셋 저장, 또는 환경변수 `ROBOT_FACTORY_DB`로 공장마다 다른 DB 파일 사용 |

### 11. 현재 버전의 제한 사항

- **AI 관제는 규칙 기반(MockAgent)** 입니다. 정해진 표현 패턴을 인식하며, 자유로운 대화나 복잡한 질문은 이해하지 못합니다. RAG + LLM 에이전트는 연동 예정입니다.
- **업체 서버 연동 API(`ConfigAPIClient`)는 오프라인 스텁**입니다. 현재는 DB 파일 공유 방식으로만 연동됩니다.
- 로봇끼리의 **충돌·교행(길 비켜주기)은 모델링하지 않습니다.** 같은 경로를 여러 대가 동시에 지날 수 있습니다.
- 주문 1개(수량 1)는 설비 1곳에서의 가공 1회로 모델링하며, 여러 공정을 순서대로 거치는 흐름(라우팅)은 지원하지 않습니다.
- DB의 주문 진행률(`completed`)은 **화면에 표시 중인 방식**의 결과로 기록됩니다.
- 시뮬레이션은 **정지/리셋 시 시간 0부터** 다시 시작되며, 진행 중이던 주문은 DB에 기록된 진행률부터 이어서 생산합니다.

### 12. 용어 정리

| 용어 | 뜻 |
|---|---|
| 시뮬레이션 시간 (sim-time) | 가상 공장 안에서 흐르는 시간. 배속에 따라 실제 시간보다 빠름 |
| 작업 (Task) | 로봇이 설비로 가서 한 번 가공하는 단위 일. 주문 수량 1개 = 작업 1건 |
| 일반 작업 | 주문과 관계없이 무작위로 들어오는 작업 (평소 공장 부하) |
| 경로망 / 노드 / 엣지 | 로봇이 다닐 수 있는 길. 노드 = 교차점, 엣지 = 두 노드를 잇는 길 |
| 전용 전환 | 설비를 특정 긴급 주문만 처리하도록 지정하는 것 |
| 선점 | 덜 급한 작업을 하던 로봇을 멈추고 긴급 작업으로 돌리는 것 |
| 긴급 복귀 | 충전 중인 로봇의 충전을 중단시키고 현장으로 보내는 것 |
| 최소충전 모드 | 충전 목표를 50%로 낮춰 로봇을 빨리 복귀시키는 운영 모드 |
